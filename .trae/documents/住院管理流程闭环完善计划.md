# 住院管理流程闭环完善计划

## 一、摘要（Summary）

用户反馈【住院管理】模块流程不通畅、无法完成功能闭环。经探索需求文档与核实代码实现，确认核心断点如下：

* **双出院路径冲突（最致命）**：入院登记页「出院」按钮直调 `discharge_patient` RPC，仅置 `status=discharged` 且**不更新** **`settlement_status`**；而结算流程 `prepare_settlement` 要求 `status='admitted'` 才能生成结算单 → **直接出院的记录永远无法结算**，住院记录从此"卡死"。且 e2e 闭环测试同样绕过结算，证明两条链路从未统一。

* **AdmissionPicker 搜索必失败**：组件用 `admission_no.ilike` 搜索，但 `admissions` 表根本没有 `admission_no` 列（[migration 21 建表](file:///d:/2026-out-going-standard/maoxianqiu-net/supabase/migrations/20260806000021_inpatient.sql#L79-L99) 无此列）→ 护理管理页"搜索选择住院记录"实际不可用。

* **房间/笼位无维护界面**（用户明确指出）：API 已封装 `createRoom/createCage/updateRoom/updateCage`，但前端无任何页面调用；房态看板空状态提示"到入院登记维护房间笼位"却是死链。

* **护理任务无法脱离计划创建**：`nursing/index.vue` 新建任务时 `petId` 取自第一条护理计划，无计划则报错。

* **自动计费无触发入口**、**费用明细无展示**、**页面间无互跳**、**结算页统计含不可结算脏数据**。

本计划按用户确认范围（**住院闭环全量完善**）与出院入口决策（**移除直出按钮，统一走结算**）制定，分 8 个实施任务 + 1 项后续方向。

### 任务 1：统一出院入口，修复双出院路径冲突（P0-1）

**目标**：所有出院必须经「生成结算单 → 收款/减免 → 完成出院」，符合 PRD 状态机与 S3.1-C "正常未结算不可 discharge"。

1. **[admission/index.vue](file:///d:/2026-out-going-standard/maoxianqiu-net/apps/maoxianqiu/src/views/inpatient/admission/index.vue)**：

   * 删除 `onDischarge` 函数（L222-244）与操作列「出院」按钮（L378-380）。

   * 操作列改为：`admitted` → 「换房」+「去结算」；`discharged` → 无操作（或只读）。

   * 「去结算」点击 `router.push('/inpatient/settlement')`（不传参，结算页自行按门店过滤）。
2. **[settlement/index.vue](file:///d:/2026-out-going-standard/maoxianqiu-net/apps/maoxianqiu/src/views/inpatient/settlement/index.vue)**：

   * `getDataList` 过滤：`unsettled` 仅保留 `status==='admitted'` 的可结算记录（`listAdmissions` 返回字段含 `status`，前端过滤即可）。

   * `pendingSettleCount`（L63）改为统计 `status==='admitted' && settlement_status==='unsettled'`。

   * 「生成结算单」按钮仅对 `status==='admitted' && settlement_status==='unsettled'` 渲染。

   * 结算行操作补充「查看住院明细」（费用/病程/护理入口，见任务 6）。
3. **历史脏数据修复**：新增一次性迁移 `supabase/migrations/20260811000000_inpatient_settlement_data_repair.sql`：

   * 检测并修复历史 `status='discharged' AND settlement_status='unsettled'` 记录：将其 `settlement_status` 置为 `finalized`（保留 discharged，视同历史直出已结案，避免死数据残留在结算待办）；输出审计说明。

   * 若不存在脏数据，脚本为幂等空操作。
4. **e2e 同步**（见任务 8）。
