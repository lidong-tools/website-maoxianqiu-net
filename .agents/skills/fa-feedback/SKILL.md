# 项目内反复修改复盘

在同一功能点进入第 3 轮及以上调整时，先提炼稳定约束，再继续实现，避免重复偏离业务目标。

## 执行流程

1. 回顾用户最初目标、历次反馈和当前明确要求。
2. 区分稳定约束与本轮新增约束，识别此前偏差来自业务理解、页面结构还是组件能力。
3. 用一句简短进度说明告知用户本轮将如何纠偏，不阻塞当前任务，不要求用户额外确认。
4. 将稳定约束直接落实到代码、配置或文档中，并按风险运行验证。
5. 在最终交付中简要说明本轮纠正了哪些理解偏差。

## 项目边界

- 本项目是独立产品，不代表任何外部框架。
- 不得自动创建外部反馈、Issue、Discussion 或跳转链接。
- 除非用户明确要求，不讨论或联系外部框架作者、维护者或社区。
- 复盘仅服务于当前项目交付，不中断正常实施流程。
