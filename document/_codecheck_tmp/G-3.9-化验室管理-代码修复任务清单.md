## 一、真实缺口（需修复）

### R-1 3.9.2-02 化验结果录入断链（判定：不完整实现）

- **现状**：检验工作台（结果录入/提交审核/审核双签/发布 RPC/危急值告警）骨架完整，但**运行期无任何代码创建 `lab_order_analytes` 结果行**——真实开单后右侧结果区恒为「暂无结果项」，结果录入→送审→发布整条链路由此断裂。证据：
  - `apps/maoxianqiu/src/api/modules/diagnostics.ts` L688-700 `batchCreateAnalytes` 已定义但全项目无任何视图调用（仅注释「可选」）；
  - `api/routes/diagnostics.ts` L274-340 `POST /lab-orders` 仅 insert `lab_orders`（status=requested），不生成结果项；
  - `supabase/migrations/20260810000301_clinical_plan_commit.sql` L117-123 `commit_clinical_plan` RPC 同事务只插 `lab_orders`；
  - 仅 `scripts/seed-demo-data.mjs` L1408 造数时直接插入 `lab_order_analytes`，可作插入字段参照。
- **修复内容**：
  1. 打通「开单 → 生成结果行」：开单仅带 `panel_id`/`catalog_item_id`（可空），需先在 `catalog_items`↔`lab_panels`↔`lab_analytes` 间建立绑定（catalog_items 现只有 `billing_type='exam'`，无 panel 关联列，migration 00016），使开单能解析出 analyte 清单；
  2. `POST /lab-orders` 成功后（Hono 端）同事务按 panel 下 `lab_analytes` 批量生成 `lab_order_analytes` 占位行（可复用 `batchCreateAnalytes` 逻辑，建议上收为服务端 Command 避免浏览器直连写）；
  3. `commit_clinical_plan` RPC 内同步插入 `lab_order_analytes` 占位行（与 lab_orders 同事务），保证「随诊疗方案一并提交」路径不再次断链；
  4. 发布/审核 RPC（`publish_lab_results` migration 00022 L1228-1310、`review_lab_results` L1320-1387）无需改动，结果行存在后即可流转。
- **涉及位置**：
  - `api/routes/diagnostics.ts`（L274-340 createLabOrderSchema + POST /lab-orders）
  - `supabase/migrations/20260810000301_clinical_plan_commit.sql`（commit_clinical_plan 内 lab_orders 插入段 L117-123）
  - `apps/maoxianqiu/src/api/modules/diagnostics.ts`（L688-700 batchCreateAnalytes 接入或上收）
  - `apps/maoxianqiu/src/views/diagnostics/lab/index.vue`（L243-280 onShowDetail 加载结果项，修复后即出现可录行）
  - 参考：`scripts/seed-demo-data.mjs` L1408（结果行字段取值样例）
- **优先级**：P0
- **验证方式**：医生工作台开检验单（单开 + 随诊疗方案提交两种路径）→ 检验工作台选中该单 → 右侧出现与 panel 项目对应的结果行 → 录入→提交审核→审核通过→已发布；查看 `lab_order_analytes` 表存在随单生成的行。

### R-2 3.9.2-04 报告插入病历（判定：未实现）

- **现状**：全库无 `source_lab_result_id` 列、无任何「插入已发布检验结果」入口。证据：
  - `apps/maoxianqiu/src/views/clinical/workbench/components/EncounterEditor.vue` 全文（主诉/现病史/体格检查/诊断/治疗方案/复诊 6 字段）无引用入口；
  - 病历详情 `apps/maoxianqiu/src/views/clinical/encounter/detail.vue` 同样无入口；
  - 现有 `medical_lab_refs` 表（migration 20260809000047 L72-95）语义是「住院医嘱↔检验申请」关联（`link_type in ('order_request','result_followup')`），`link_medical_lab_ref` RPC（L312-369）与前端 `linkMedicalLabRef`（`apps/maoxianqiu/src/api/modules/clinical.ts` L526）均无视图调用——**不适用**于「病历引用已发布结果」；
  - 需求依据：PRD §12.2 L633「发布后医生可一键引用到病历」、S31 §6「引用必须保留 `source_lab_result_id`，不得只复制文本」。
- **修复内容**：
  1. **表**：新建病历引用表（建议 `encounter_lab_result_refs`：`encounter_id`、`pet_id`、`lab_order_id`、`source_lab_result_id` 外键引用 `lab_order_analytes(id)`、`snapshot jsonb`（引用时的结果快照，保证修订后旧引用内容不受破坏）、`target_field`（插入到病历的哪个字段）、`sort_order`、`created_by`），RLS 跟随 encounter（encounter.view/clinical 权限族）；
  2. **API**：Hono Command `POST /clinical/encounters/:id/lab-result-refs`（校验同租户、宠物一致、仅已发布结果可引用）+ 列表/删除接口，禁止浏览器直连写；
  3. **UI**：`EncounterEditor.vue` 增加「插入检验结果」入口（弹窗列出该 pet 已发布检验单→点选后把结果快照文本追加到指定字段（如现病史），同时落库引用记录）；`encounter/detail.vue` 病历展示区展示引用块（来源申请单 + 修订后可追溯）；
  4. `medical_lab_refs` 维持现状（医嘱关联语义），不强行复用。
- **涉及位置**：
  - 新建 supabase migration（引用表 + RLS）
  - `api/routes/clinical.ts`（新增路由，参照现有 Hono Command 写法）
  - `apps/maoxianqiu/src/api/modules/clinical.ts`（新增方法）
  - `apps/maoxianqiu/src/views/clinical/workbench/components/EncounterEditor.vue`（引用入口 + 弹窗）
  - `apps/maoxianqiu/src/views/clinical/workbench/composables/useEncounterDraft.ts`（L11-18 EncounterFormState 关联引用）
  - `apps/maoxianqiu/src/views/clinical/encounter/detail.vue`（引用块展示）
- **优先级**：P0
- **验证方式**：发布一条检验结果 → 诊疗模块打开该 pet 病历 → 编辑器中插入已发布结果 → 病历中显示结果文本且 `encounter_lab_result_refs` 落库（`source_lab_result_id` 非空）→ 修订该结果后，病历中旧引用文本不变（快照生效）。

### R-3 3.9.2-05 结果修订机制（判定：未实现）

- **现状**：检验领域**无 revise 接口、无版本表（`diagnostic_report_versions` 未建）、无 `result_version` 列、无修订按钮**，已发布结果完全只读（`deriveLabWorkflow` 对 approved 返回 `canEditResult=false`，`api/routes/diagnostics.ts` L818-820）。「禁止覆盖」已实现，但设计文档承诺的「版本化修订替代方案」（change_reason/created_by/verified_by，映射矩阵 L64「手工改结果→报告修订」）从未落地。影像侧已有完整对等机制可参照：`imaging_reports.version` + `(imaging_order_id, version)` 唯一约束（migration 20260810000059 L45-66）+ 修订入口 `onCreateRevision`（`apps/maoxianqiu/src/views/diagnostics/imaging/index.vue` L279-293）+ `publish_imaging_report` RPC（migration 61）。
- **修复内容**：
  1. **表**：新建 `lab_result_versions`（或按设计文档 §24 建 `diagnostic_report_versions`）：`lab_order_id`、`analyte_id`、`version`、`result_value/result_numeric`、`flag`、`snapshot jsonb`、`change_reason`（必填）、`created_by`、`verified_by`、`verified_at`，`(lab_order_id, analyte_id, version)` 唯一，参照 `imaging_reports` 设计；
  2. **RPC**：`revise_lab_results`（仅已发布可修订：复制当前结果为新版本 + 更新当前值 + 写审计；change_reason 必填；双签：修订人≠原录入人，可参照 `review_lab_results` 双签校验 migration 00022 L1320-1387）；
  3. **API**：Hono Command `POST /diagnostics/lab-orders/:id/revise`（新权限码 `lab.result.revise`，参照 `publish_lab_results` 路由 L365-389 写法；同步在 `supabase/seed.sql` 与权限清单维护新权限码）；
  4. **UI**：`lab/index.vue`「已发布」Tab 增加「修订」按钮（参照 imaging L279-293），修订表单（结果值 + 变更原因）+ 版本历史展示；已发布单仍保持只读（不可直接改原值）。
- **涉及位置**：
  - 新建 supabase migration（版本表 + revise RPC + 权限码）
  - `api/routes/diagnostics.ts`（新增 revise 路由，参照 L365-389 publish 路由）
  - `apps/maoxianqiu/src/api/modules/diagnostics.ts`（新增 reviseLabResults 方法）
  - `apps/maoxianqiu/src/views/diagnostics/lab/index.vue`（修订按钮 + 弹窗 + 版本历史）
  - `apps/maoxianqiu/src/types/diagnostics.ts`（版本记录类型）
  - 参照：`apps/maoxianqiu/src/views/diagnostics/imaging/index.vue` L279-293、migration 20260810000059 L45-66
- **优先级**：P0
- **验证方式**：已发布检验单出现「修订」入口 → 填写新值 + 变更原因提交 → 当前结果更新、`lab_result_versions` 新增版本行（change_reason/created_by 非空）→ 版本历史可见旧值；普通 update 已发布结果仍被拒绝（canEditResult=false + RLS 双重保障不变）。

### R-4 3.9.1-02 化验项目维护（判定：不完整实现）

- **现状**：panel（检验组合）维护已有 UI（`apps/maoxianqiu/src/views/catalog/index.vue` L731-779 `onCreateLabPanel/onToggleLabPanelActive/onDeleteLabPanel`），但 **analyte（化验项目明细：名称/单位/参考范围/分类）无任何前端维护 UI**——后端 CRUD 齐全（`api/routes/catalog.ts` L905-1100 `/lab-analytes` GET/POST/PATCH/DELETE，RLS 按 catalog.manage），前端无页面调用；且 `lab_panels`/`lab_analytes` 表（migration 00016 L155-187）**均无 `report_template`、`is_outsourced`（是否外送）字段**（PRD-v0.5 P1 项，全库检索 `report_template|is_outsourced` 零命中）。
- **修复内容**：
  1. **表**：migration 给 `lab_analytes` 增 `report_template text`、`is_outsourced boolean not null default false`（`lab_panels` 如需可加 `report_template`，P1 可先做 analyte 级）；
  2. **API**：`api/routes/catalog.ts` lab-analytes CRUD 已存在，补充新字段的 schema 透传；
  3. **UI**：`catalog/index.vue` 检验 panel Tab（L1220-1308）增加 analyte 明细管理（panel 下项目列表：名称/单位/参考范围文本/分类/是否外送 的增删改，可复用 `openSimpleFormModal` 模式，参照 L731-779）；
  4. **联动**：analyte 维护后需可被开单路径引用（与 R-1 的 panel→analyte 绑定共用同一数据源）。
- **涉及位置**：
  - 新建 supabase migration（加字段）
  - `api/routes/catalog.ts`（L905-1100 lab-analytes CRUD 补字段）
  - `apps/maoxianqiu/src/views/catalog/index.vue`（L1220-1308 检验 panel Tab 增 analyte 管理 UI）
  - `apps/maoxianqiu/src/types/catalog.ts`（LabAnalyte 类型补字段）
- **优先级**：P1
- **验证方式**：目录管理→检验 panel→选中 panel 可增删改 analyte（名称/单位/参考范围/是否外送）→ 保存后接口落库、列表可查；`lab_analytes` 表新字段存在。

### R-5 3.9.2-02/03 检验工作台展示与确认补强（判定：不完整实现，顺手小修）
