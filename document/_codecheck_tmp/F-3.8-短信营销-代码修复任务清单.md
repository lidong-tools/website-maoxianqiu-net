## 一、真实缺口（需修复）

### R-1 3.8.1-01 疫苗提醒一体化发送（判定：不完整实现）
- 现状：
  - 疫苗接种页 `apps/maoxianqiu/src/views/diagnostics/vaccination/index.vue` 全文无「短信/发送/提醒」入口，仅展示疫苗记录表格；
  - 疫苗/驱虫到期提醒由 `scan_diag_reminders` RPC（`supabase/migrations/20260806000022_diagnostics.sql` L1078）生成，**仅写 `diag_reminders` 表，不写 `message_deliveries`、不产生任何发送**；
  - 「诊断提醒」页 `apps/maoxianqiu/src/views/diagnostics/reminder/index.vue` L113 `onScan` 只有「扫描到期提醒(RPC)」按钮 + 取消，无发送动作；
  - 系统仅有通用手动发送链路（消息中心发送 Tab → `POST /messaging/send`，`api/routes/messaging.ts` L276 → `api/services/messaging/engine.ts` `sendMessage` L371），无「查找客户→选中→选疫苗→勾选内容→确定→记账」的疫苗提醒专用流程。
- 修复内容：
  1. 后端：新增批量发送 API（如 `POST /diagnostics/reminders/send`，`api/routes/diagnostics.ts`）：接收选中的 `diag_reminders` id 列表 → 按 `reminder_type` 匹配场景模板 code（`vaccine_reminder`/`deworming_reminder`）→ 复用 `engine.ts` `sendMessage` 真实发送（scene=vaccine_reminder，渲染 customer/pet 变量）→ 回写 `diag_reminders.status='sent'`、`sent_at`。
  2. 前端：诊断提醒页 `reminder/index.vue` 增加「发送所选」按钮（勾选 pending 行批量发送）；疫苗接种页 `vaccination/index.vue` 增加「发送提醒」快捷入口（跳转诊断提醒页或直接发起发送），对齐竞品一体化流程。
  3. （可选）扩展 `scan_diag_reminders` 或新增 RPC 直接生成 queued 投递，由统一投递消费逻辑发送（见 R-2）。
- 涉及位置：
  - `apps/maoxianqiu/src/views/diagnostics/reminder/index.vue`（L113 onScan 附近增加发送操作）
  - `apps/maoxianqiu/src/views/diagnostics/vaccination/index.vue`（增加发送入口）
  - `api/routes/diagnostics.ts`（新增发送端点）
  - `api/services/messaging/engine.ts`（复用 sendMessage，基本无改动）
  - `supabase/migrations/20260806000022_diagnostics.sql`（`scan_diag_reminders` L1078，如需扩展为生成投递）
- 优先级：P0
- 验证方式：① 手工路径：诊断提醒页扫描→勾选 pending 提醒→发送→消息中心投递记录出现 sent（provider_message_id 非空）；② 接口测试：`POST /diagnostics/reminders/send` 返回发送数，`diag_reminders.sent_at` 落库；③ 配置 `MESSAGING_SMS_*` 后手机号可收到真实短信。

### R-2 3.8.1-04 定时/自动触达闭环（cron 调度，判定：不完整实现）
- 现状：
  - `vercel.json` 无 `crons` 配置（全文件仅 rewrites）；
  - api 目录无 cron/setInterval/worker 调度代码；`jobs` 表 reminders 队列（`20260807000023_operations_rpc_complete.sql` L133-139 写入）在 api 层**无消费者**；
  - 旧链路 `scan_reminders`（`20260807000023_operations_rpc_complete.sql` L30）生成的 queued 投递只能人工在投递记录页手动发送，且 `send_delivery` RPC（同文件 L162）为 **Mock 模拟发送**（mock-sms），不经过真实 Provider；
  - 预约/疫苗/复诊等业务模块均未向 `message_deliveries` 写入提醒投递；生日 campaign 无到日自动发送。
- 修复内容：
  1. `vercel.json` 增加 `crons`（如每天 09:00 调 `/api/cron/reminders`、每天 08:00 调 `/api/cron/campaigns`）。
  2. 新增 `api/routes/cron.ts`（cron 处理器：鉴权 header + 幂等）：
     a. 调 `scan_diag_reminders` + `scan_reminders` 生成到期提醒与 queued 投递；
     b. 消费 `message_deliveries` status='queued'（分批）→ 调 `engine.ts` `sendMessage` 走真实 Provider（替换 `send_delivery` Mock 链路，或新增真实发送 RPC）；
     c. 扫描 `starts_at<=now` 且 `status='scheduled'` 的 `marketing_campaigns` → 触发发布（见 R-3）。
  3. 为 `jobs` 表 reminders 队列增加消费者端点（或直接按 queued 投递消费，可不下发 jobs）。
- 涉及位置：
  - `vercel.json`（加 crons）
  - `api/routes/cron.ts`（新增）
  - `api/routes/operations.ts`（`/reminders/scan` L114 可复用为 cron 内部调用）
  - `api/services/messaging/engine.ts`（sendMessage 复用）
  - `supabase/migrations/20260807000023_operations_rpc_complete.sql`（`send_delivery` L162 保留 Mock 或改由 API 层真实发送）
- 优先级：P0
- 验证方式：① 本地手工触发 `POST /api/cron/reminders`（可带 dryRun）→ 到期提醒生成投递并真实发送、状态 sent；② 配置 vercel crons 后检查 schedule 触发日志；③ 到期的预约/疫苗/生日场景在无人工操作下自动生成投递记录。

### R-3 3.8.2-03 Campaign 发布后触发投递发送（判定：不完整实现）
- 现状：
  - `marketing_campaigns.message_template_id` 字段存在（`20260810000223_marketing_campaign_referral.sql` L33）且前端保存（`campaigns/index.vue` L266/L568），但仅存 UUID，无模板存在性校验/预览；
  - `publish_campaign` RPC（`20260810000223_marketing_campaign_referral.sql` L240）只做 Audience Snapshot + 建 Run，文件头注释明确「Marketing 不直接发送消息/写 message_deliveries」，**无 send_delivery 触发**；
  - `POST /marketing/campaigns/:id/publish`（`api/routes/marketing.ts` L1049-1076）仅调 RPC；`marketing_campaign_runs.dispatch_count` 恒为 0。
- 修复内容：
  1. 扩展 `publish_campaign` 或新增 RPC `dispatch_campaign_run`：按 run_id 关联 audience + `campaign.message_template_id` + channel，逐客户渲染模板变量生成 `message_deliveries`（queued，scene=marketing/birthday，关联 campaign_id/run_no）。
  2. queued 投递由 R-2 统一消费逻辑真实发送（或发布端点内直接调 `engine.sendMessage`）。
  3. 前端 `campaigns/index.vue` 发布后展示 `dispatch_count`/投递进度；`messageTemplateId` 输入（L567-569）加模板存在性校验与预览。
- 涉及位置：
  - `supabase/migrations/20260810000223_marketing_campaign_referral.sql`（`publish_campaign` L240 后新增 dispatch RPC）
  - `api/routes/marketing.ts`（L1049 publish 端点，发布后触发 dispatch）
  - `api/services/messaging/engine.ts`（发送复用）
  - `apps/maoxianqiu/src/views/marketing/campaigns/index.vue`（L567-569 模板校验/预览）
- 优先级：P0
- 验证方式：① 创建 type=birthday + message_template_id 的 campaign → 发布 → `marketing_campaign_runs.dispatch_count>0`、`message_deliveries` 出现 queued→sent 记录；② 投递记录按场景筛选可见；③ campaign 详情展示实际触达数。

### R-4 3.8.1-02 医院电话/地址变量化（判定：已实现，顺手小修）
- 现状：模板变量白名单（`api/services/messaging/template-engine.ts` L19-30）含 `customer.name`/`pet.name`/`store.name`/`hospital.name`/`doctor.name` 等，但无 `doctor.phone`/`hospital.phone`/`hospital.address` 等 key；竞品示例短信中的电话/地址只能手写进模板正文，无法变量化渲染。
- 修复内容：白名单增加 `hospital.phone`/`hospital.address`（或 `store.phone`/`store.address`），发送时从门店/医院档案填充；前端「可用变量」按钮同步（数据源 `GET /messaging/variables`）。
- 涉及位置：
  - `api/services/messaging/template-engine.ts`（L19-30 白名单 + 渲染）
  - `api/services/messaging/engine.ts`（变量注入）
  - `api/routes/messaging.ts`（/variables 端点）
  - `apps/maoxianqiu/src/views/operations/messaging/index.vue`（L683-692 变量按钮）
- 优先级：P2
- 验证方式：模板编辑点「医院电话」插入 `{{hospital.phone}}` → 发送 → `content_snapshot` 渲染为实际号码。
