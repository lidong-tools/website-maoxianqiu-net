## 一、真实缺口（需修复）

### R-1 3.1-04 医院地址字段（判定：不完整实现）

- **现状**：竞品注册表单收集"医院地址、详细地址"两级地址；当前实现仅门店（store）有**单一 `address` 字段**，医院级地址与详细地址两级结构均缺失：
  - `tenants` 表无任何地址列（`supabase/migrations/20260806000008_tenants.sql` L9-22，仅 slug/name/short_name/logo_file_id/timezone/currency/locale/status/trial_ends_at）
  - 租户初始化向导入参无地址（`apps/maoxianqiu/src/views/system/tenant-init/index.vue` model L39-48：tenantSlug/tenantName/storeName/storeCode/ownerUserId/ownerName/ownerPhone/timezone）
  - 系统设置-医院信息 Tab 无地址（`apps/maoxianqiu/src/views/system/settings/index.vue` L568-591：仅名称/简称/时区/币种/语言）
  - 仅门店表单有单一"地址"字段（`apps/maoxianqiu/src/views/system/store/components/StoreForm.vue` L115-117；`apps/maoxianqiu/src/api/modules/store.ts` L44-98 create/update 支持 address；stores 表 `supabase/migrations/20260806000003_rbac.sql` L20-28 仅 `address text`）
- **修复内容**：
  - 数据表：新增 migration，`tenants` 增加 `address text`（医院地址）+ `detail_address text`（详细地址），参考 PRD §4.2 企业主体信息；可复用 `stores.address` 单列作为门店地址（不强制拆两级）
  - 初始化入参链路：`api/routes/tenants.ts` `/initialize` 的 `initializeSchema` 增加地址入参（L47-103 校验/透传）→ `initialize_tenant` RPC 签名增加 `p_address`/`p_detail_address`（`supabase/migrations/20260809000036_tenant_init_rpc.sql` L25-37）→ RPC 内更新 tenants 地址（可在 L79-83 时区归一附近一并写入）+ 首店创建时写入 `address`（L189-191 当前仅插 name/code/status）
  - 前端表单：`views/system/tenant-init/index.vue` 表单增加医院地址/详细地址输入项（含新建租户分支与已选租户分支）；`views/system/settings/index.vue` 医院信息 Tab 增加地址字段并在 `saveTenant` 提交
  - 展示：平台租户管理列表/详情（`views/system/tenants/index.vue`、`tenants/detail.vue`）可选展示地址，非必需
- **涉及位置**：
  - `supabase/migrations/`（新增 tenants 地址列 migration）
  - `supabase/migrations/20260809000036_tenant_init_rpc.sql`（RPC 签名 + 写入逻辑）
  - `api/routes/tenants.ts`（initializeSchema + initialize 透传）
  - `apps/maoxianqiu/src/views/system/tenant-init/index.vue`（表单字段）
  - `apps/maoxianqiu/src/views/system/settings/index.vue`（医院信息表单）
  - `apps/maoxianqiu/src/api/modules/tenant.ts`（initialize 请求体类型）
- **优先级**：P1（功能字段补齐，不阻塞系统可用性与既有初始化链路；但为 3.1-04"医院注册信息表单"需求点的核心验收缺口）
- **验证方式**：① 新 migration 应用后 `tenants` 表存在 address/detail_address 列；② 平台管理员经初始化向导新建租户并填地址，初始化完成后 tenants 行与首店均落库地址；③ 系统设置-医院信息可编辑并保存地址；④ 门店表单地址仍正常（回归）

## 二、产品决策项（无需修复或需确认）

### D-1 3.1-02 付费订阅计费闭环（判定：未实现，属"淘汰激活码→SaaS 订阅"产品演进缺口，需确认）

- **现状**：激活码逻辑全仓无命中（符合 07 差异矩阵 L19"有意淘汰"）；替代方案部分落地——tenants 表已有 `status(active/trial/suspended)` + `trial_ends_at`（`supabase/migrations/20260806000008_tenants.sql` L18-19）、停用后新业务拦截双向落地（Hono `api/lib/permission.ts` resolveScopedAccess L425-440 + RLS `is_tenant_business_active` `supabase/migrations/20260810000093_permission_helper_restore.sql` L25-38）、平台租户管理停用/恢复可用（`views/system/tenants/index.vue`）。但 **tenants 表无 `subscription`（订阅方案）字段（PRD §4.2 规划的字段未落地）、全库无订阅/计费/续费代码**。
- **决策建议**：订阅计费是否在本阶段（Pilot）范围内，需与产品/项目负责人确认。
  - 若确认不在本阶段范围：维持现状（租户状态 + 停用拦截已闭环试用/停用管理），本项关闭，但建议在 PRD/待确认问题记录中明确"付费订阅计费后置"。
  - 若确认需要：另立任务实现——① tenants 增加 `subscription` 字段（如 subscription_plan/subscription_ends_at，migration）；② 订阅/续费/到期处理业务模块（含计费单据表、到期自动停用任务）；③ 前端订阅管理界面（租户管理页或系统设置）。
- **优先级**：待确认（若确认要做，建议 P1）
