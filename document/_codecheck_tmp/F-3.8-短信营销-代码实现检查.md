**总览结论**：毛线球以「消息中心」（`/operations/messaging`，S32-D 真实 Provider 体系）整体承接 3.8 章节。**发送短信（手动）**、**短信模板**、**已发短信**三类能力真实可用（真实 SMS Provider + Webhook 回执 + 幂等/CAS 状态机）；**「疫苗提醒一体化流程」「定时/自动触达闭环」「场景→模板自动关联」三条自动链路均未闭合**（无 cron 定时任务、Campaign 发布不触发发送、疫苗模块不写投递）；**短信条数购买/余额**确认无任何代码（商业模式差异，预期无）。

## 3.8.1-01 疫苗提醒短信发送流程（查找/选中客户→选择疫苗→勾选内容→确定→记账）

- 功能界面：⚠️ — 无「疫苗场景」一体化发送界面。疫苗接种页 `apps/maoxianqiu/src/views/diagnostics/vaccination/index.vue` 全文检索「短信/发送/messaging/提醒」无命中（仅错误提示文案），无任何发送入口；疫苗/免疫模块与消息发送完全无代码关联。存在通用手动发送界面：`apps/maoxianqiu/src/views/operations/messaging/index.vue`（发送 Tab，选模板→填接收人→填变量→发送）。
- 界面功能实现：⚠️ — 通用发送表单真实可用（messaging/index.vue L284-337 `submitSend`，含模板选择/渠道/场景/接收人/变量/幂等键）；但无「查找客户→选中→选择疫苗→勾选内容→记账」的疫苗提醒专用流程。
- 业务流转流程：⚠️ — ① `POST /messaging/send` 真实实现（api/routes/messaging.ts L276-313 → api/services/messaging/engine.ts `sendMessage` L371，支持 recipient/template/variables/scene/idempotencyKey）。② 疫苗模块无任何写 message_deliveries 的调用：`scan_diag_reminders` RPC（supabase/migrations/20260806000022_diagnostics.sql L1078）只向 `diag_reminders` 表插入疫苗/驱虫到期提醒记录，**不产生投递、不发送**；前端「诊断提醒」页（views/diagnostics/reminder/index.vue）仅有「扫描到期提醒/取消」按钮，无发送动作。③ 存在另一条旧链路（reminders 表）：`scan_reminders` RPC（20260807000023_operations_rpc_complete.sql L30）按模板 code 匹配渲染后写 message_deliveries(queued)，但由 `POST /operations/reminders/scan`（api/routes/operations.ts L114）**手动触发**，且 `send_delivery` RPC（同迁移 L162）是 **Mock 模拟发送**（mock-sms），不经过真实 Provider。④ `publish_campaign` RPC（20260810000223_marketing_campaign_referral.sql L240）仅 Snapshot Audience + 建 Run，文件头注释明确「Marketing 不直接发送消息/写 message_deliveries（走 Agent-08 Messaging Contract）」，无 send_delivery 触发。
- 判定：**不完整实现**
- 说明：通用消息发送能力完备，但「疫苗/免疫模块内嵌一体化提醒发送」不存在；营销 Campaign 发布后触达发送也缺失（依赖的 Agent-08 侧未实现）。

## 3.8.1-02 短信内容要素（提醒文案 + 客户姓名 + 宠物/疫苗信息 + 医院电话/地址 + 品牌签名）

- 功能界面：✅ — 模板编辑支持占位符插入（messaging/index.vue L679-694 可用变量按钮 → L150-153 `insertVariable` 插入 `{{key}}`），模板正文可自由编排提醒文案。
- 界面功能实现：✅ — 发送时按模板渲染内容快照并在结果弹窗展示（messaging/index.vue L711-715）。
- 业务流转流程：✅ — ① 模板变量白名单（api/services/messaging/template-engine.ts L19-30）：`customer.name` 客户姓名、`pet.name` 宠物姓名、`store.name` 门店名称、`hospital.name` 医院名称、`doctor.name` 医生姓名、`appointment.time/type`、`order.total` 等，覆盖姓名/宠物/门店/疫苗相关字段。② SMS 发送附加品牌签名：api/providers/sms.ts L54 请求体携带 `sign: this.config.sign`，来源服务端环境变量 `MESSAGING_SMS_SIGN`（api/services/messaging/config.ts L49）。⚠️ 白名单无「电话/地址」专用变量（无 doctor.phone/hospital.phone/address 等 key），医院电话/地址需在模板正文手动写死，未做成变量化渲染。
- 判定：**已实现**
- 说明：内容要素（文案+姓名+宠物/疫苗信息+门店/医院名称+签名）均已支撑；唯一小差距为电话/地址无专用变量，仅能手动填正文。

- 功能界面：✅ — 消息中心「投递记录」Tab（messaging/index.vue L592-647）+ 投递详情弹窗（L719-756，含每次尝试的 provider/状态/错误码/请求快照）。
- 界面功能实现：✅ — 列表展示渠道/接收人/场景/状态（sent 绿、failed 红着色）/尝试次数/创建/发送时间；状态筛选、渠道筛选、场景筛选；详情查看尝试历史与 Provider ID；failed/retry 可手动重试（`onRetry` L417，`POST /messaging/deliveries/:id/retry`）。
- 业务流转流程：✅ — `GET /messaging/deliveries`（api/routes/messaging.ts L316-356）返回全字段：status/channel/recipient/content_snapshot/subject_snapshot/variables_snapshot/provider_message_id/error/attempts/sent_at；`GET /messaging/deliveries/:id`（L359-379）含 `message_delivery_attempts` 尝试历史；状态机 queued→sending→sent/delivered/failed/retry（engine.ts L68-69，migration 112 L24-25）；发送成功写 provider_message_id、失败写 error（engine.ts `recordAttempt` L274-336）；Webhook 回执 CAS 推进状态（migration 267 `apply_provider_event` L70+，messaging-webhook.ts L79-162 验签/幂等落库）。
- 判定：**已实现**

## 3.8.1-04 定时/定点发送（预约提醒、生日提醒、诊疗提醒等）

- 功能界面：⚠️ — 无「定时规则配置」界面；营销活动（views/marketing/campaigns/index.vue）支持 type=birthday 生日活动与 startsAt/endsAt 排期字段（L200-204），但仅是活动元数据。
- 界面功能实现：⚠️ — 「诊断提醒」页有手动「扫描到期提醒」按钮（reminder/index.vue L113-135 onScan，调 `scan_diag_reminders`，仅生成 diag_reminders 提醒记录，不发送）；旧 operations 链路 `POST /operations/reminders/scan`（operations.ts L114）手动扫描 reminders 生成投递队列，但发送仍要人工在投递记录页点按钮。
- 业务流转流程：❌ — ① **无任何定时任务**：vercel.json 无 `crons` 配置，api 目录无 cron/setInterval 调度代码。② marketing campaign 发布（publish_campaign RPC）不触发发送（见 3.8.1-01）。③ scan_reminders 写入 `jobs` 队列（queue='reminders'，20260807000023 L134-139），但 api 中**无该队列消费者**，job 仅落库不消费。④ 预约/疫苗/复诊等业务模块均未向 message_deliveries 写提醒投递（全仓检索 sendMessage/send_delivery 调用方，仅 messaging 路由与旧 operations 模拟链路）。⑤ 生日触达：campaign type=birthday 仅按当月生日 snapshot 客户名单（publish_campaign L282-293），无到日自动发送。
- 判定：**不完整实现**
- 说明：场景枚举（预约提醒/疫苗提醒/回访提醒/检验报告）与生日 Campaign 规则均具备，但「到期自动扫描→自动发送」闭环缺失——所有触发均为手动 API/按钮，无 cron 定时驱动。

### 主要差距说明

**发送短信（3.8.1）**
- 手动发送能力完整（真实 SMS Provider + 模板渲染 + 幂等 + 回执），但两条自动链路缺失：
  1. **疫苗提醒一体化流程**：vaccination 模块 → scan_diag_reminders 只写 diag_reminders 提醒表，无 message_deliveries 写入、无发送调用；`views/diagnostics/vaccination/index.vue` 无任何发送入口。

- 内容要素小差距：模板变量白名单无「医院电话/地址」专用变量，需正文手写。

**短信模板（3.8.2）**
- 模板 CRUD、变量白名单校验（保存+发送双校验）、变量点击插入、版本管理均完整；「场景→模板→自动关联发送」缺闭环（campaign 只存 message_template_id 不消费）。

**已发短信（3.8.3）**
- 投递记录列表/筛选/详情/重试/Webhook 回执状态推进均完整实现，无差距。

**短信服务（3.8.4）**
- 短信条数购买、余量显示确认无任何代码（UI/API/表均无），属商业模式差异导致的预期性缺口，与需求报告「无对应依据」一致。
