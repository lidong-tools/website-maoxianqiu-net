### R-1 3.5.1-04 快速入库审核（判定：不完整实现）

- **现状**：`receipt/index.vue`「入库登记」表单「确认入库」提交即调 `POST /inventory/goods-receipt` → `post_goods_receipt` RPC（`20260806000017_inventory.sql` L370-473）单事务创建批次/余额/流水，**无草稿/审核环节，提交即直接增加库存**；"审核→过账"能力仅存在于采购单路径（`approve_purchase_order`，`20260810000096_purchasing_integrity.sql` L256-289，含 SELF_APPROVAL_FORBIDDEN 禁止自审）。PRD §15.3（L827-839）与映射矩阵 L48 明确快速入库应为「草稿、审核、过账、幂等」，代码仅"幂等"落地。
- **修复内容**（需产品决策方案 A/B，见第二部分决策项 2）：
  - 方案 A（完整状态机）：新建 `goods_receipts` / `goods_receipt_items` 单据表（参照 `purchase_orders`/`purchase_order_items`，`20260810000066_purchase_orders.sql` + 完整性校验 `20260810000096` 同构）；新增 RPC `create_goods_receipt`（draft + 明细）→ `submit_goods_receipt`（draft→submitted）→ `approve_goods_receipt`（submitted→approved，含禁止自审）→ `post_goods_receipt`（approved→posted，**过账才调现有 `post_goods_receipt` 增加库存，复用幂等键强制**）；权限 `inventory.receive`；UI 入库登记改为"保存草稿"，新增入库单列表 + 详情抽屉操作区（提交审核/审核通过/过账/取消按钮，参照 `purchasing/index.vue` L642-674）。
  - 方案 B（简化决策）：明确快速入库为"直接过账"的快速通道，审核/过账由采购单路径承载——仅需在需求文档固化决策，代码可不动（不建议，PRD 冲突）。
- **涉及位置**：`apps/maoxianqiu/src/views/inventory/receipt/index.vue`（L167-210 `onSubmit` / L451-482 表单）；`api/routes/inventory.ts`（L99-179 goods-receipt，参照 L1254/1290/1326 采购 submit/approve/cancel）；新迁移文件（参照 `20260810000066/67/68/69/96`）
- **优先级**：P0
- **验证方式**：新建入库单为 draft 状态且库存不变；submit 后须 approve 才可过账；过账一次即增加库存且重复过账被幂等键拦截；无 `inventory.receive` 权限、自审被拒。

## 二、产品决策项（无需修复或需确认）

1. **删除类操作以"取消 + 不可变流水"替代物理删除**（3.5.1-05 / 3.5.4-05 / 3.5.5-05）：符合 PRD §15.4"库存流水不可变"与映射矩阵"状态和审计/不可变记录"要求，但竞品手册三处功能点均含物理删除。**需产品确认接受"无物理删除、仅取消"**——确认后 R-2/R-8/R-12 按取消实现；若要求物理删除，需另行评估单据/流水关联约束。
2. **快速入库形态**（3.5.1-04）：PRD §15.3 + 映射矩阵 L48 要求"草稿、审核、过账、幂等"完整状态机，而 Agent-05 §14 又定位快速入库为"临时补录、无采购单入库"的快速通道（L396-398）。**需决策：方案 A（完整状态机，R-1 修复）还是方案 B（直接过账快速通道，审核走采购单，代码不动仅文档固化）**。建议方案 A，与 PRD 一致。
3. **调拨状态机落地深度**（3.5.5-03/04）：PRD §15.6 定义了完整的审核/在途/部分收货/差异状态机，代码为"一次到账"原子调拨。**需决策是否本轮完整落地**（R-9 + R-11 合并实施）；若采用简化（保留一次到账），则 R-9 仅补"审核闸口"（draft/submitted/approved + 过账一次到账），R-11 的在途/部分收货可下放迭代。
4. **库存预警阈值概念**（R-14）：当前明确以"可用 ≤ 0（断货）"为口径（审计 #25 注释"避免给管理层不存在的低库存阈值概念"），而 PRD L92 提及门店可配置"库存阈值"。**需确认本轮是否引入阈值配置**（涉及数据模型 + 目录设置页 + 驾驶舱口径变更）。
5. **盘点范围选择粒度**（R-5）：竞品手册要求"选择要盘点的药品种类/商品种类"，PRD 未明确粒度。**需确认范围选项**（全部/按品类/按商品）及是否要求部分盘点时快照仅覆盖所选范围。
