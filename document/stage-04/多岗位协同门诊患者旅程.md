# 多岗位协同门诊患者旅程

## 目标与边界

门诊统一使用一条患者旅程，岗位工作台只消费服务端聚合结果，不各自维护冲突状态。首期覆盖预约、到店、分诊、候诊、接诊、处方/检验/影像、收费、执行/发药、离院、病历签署与回访；住院、手术和外部转诊只建立正式交接。

## 标准旅程

`预约 → 到店 → 分诊 → 候诊 → 叫号 → 问诊 → 医疗计划 → 收费 → 检验/影像/护理/药房执行 → 结果确认 → 离院 → 病历签署 → 回访`

候诊状态固定为：

`checked_in → triage → waiting → called → missed / in_consultation → closed`

就诊临床状态使用 `active / plan_ready / closed / cancelled / transferred`，病历归档状态独立使用 `draft / signed / archived`。患者离院不等于病历已经签署。

## 岗位职责与交接

| 岗位 | 队列 | 核心动作 | 交接去向 |
|---|---|---|---|
| 前台接待 | 待签到、已到店、候诊异常 | 签到、生成队列号、分配医生、取消/爽约 | 分诊或候诊 |
| 分诊护士 | 待分诊、急诊红旗 | 生命体征、疼痛、过敏、风险、分级 | 医生候诊 |
| 医生 | 待叫号、诊疗中、待阅报告、待签署 | 接诊、病历、诊断、处方、检验/影像申请、结束问诊 | 收银及专业执行岗位 |
| 治疗护士 | 待执行、执行中、异常 | 注射、输液、处置、观察、离院交代 | 医生或离院 |
| 检验 | 待采样、检测中、待审核、危急值 | 采样、接收、检测、审核、发布 | 医生待阅 |
| 影像 | 待排程、待执行、报告中 | 排程、采集、报告、审核、发布 | 医生待阅 |
| 收银 | 待付款、部分支付、异议 | 核对、收款、作废争议条目 | 执行岗位 |
| 药房 | 待审方、已付款待发药 | 审方、批次复核、发药、用药交代 | 离院 |
| 客服回访 | 今日、逾期、失联 | 回访、异常转医生、复诊预约 | 医生或前台 |
| 门店管理/医务 | 超时、危急值、欠费、病历逾期 | 协调、审批、转诊、强制关闭、审计 | 对应责任岗位 |

## 医疗项目与收费规则

医生开具处方、检验或影像申请时，医疗单据、`encounter_charge_items` 待付款明细、`workflow_tasks` 下游任务及 `patient_journey_events` 事件在同一数据库事务中产生。任何一项失败，医生开单整体回滚。

- 处方按药品目录价/门店价和数量逐行计费。
- 检验、影像必须绑定目录价目才能自动计费；执行岗位任务仍会生成。
- 发药、检验执行、影像执行和治疗处置默认要求费用已支付。
- 客户对单条费用提出异议时，收银员只能执行“作废”，必须填写原因。
- 作废将条目标记为 `voided`，保留原金额、来源单据、操作员工、岗位、时间和前后差异；禁止删除。
- 作废同时取消尚未执行的对应岗位任务。已支付或已进入发票的条目不能直接作废，应走退款/红冲流程。

## 操作留痕规范

`patient_journey_events` 为不可变事件表。事件记录租户、门店、客户、宠物、预约、候诊、就诊、业务单据、前一事件、实际员工、员工编号与姓名快照、当次岗位、来源工作台、请求与幂等键、前后状态和原因。数据库触发器禁止更新或删除事件，包括后台服务账号。

服务端根据当前门店员工角色解析岗位，客户端传入的岗位别名不能绕过授权。关键命令必须同时成功写入业务记录与旅程事件。

## 页面与接口

- `/workbenches/:role`：统一岗位工作台；一人多岗可切换并记忆上次岗位。
- `/clinical/waiting-display`：脱敏候诊大屏，仅显示队列号、宠物昵称、诊室和医生显示名。
- `/clinical/encounter/:id`：病历及患者旅程时间线。
- `GET /workbenches/:role`：服务端岗位聚合。
- `GET /clinical/encounters/:id/workspace|timeline`：患者工作区和不可变时间线。
- `POST /clinical/queue/*`：签到、分诊及候诊状态机。
- `POST /workflow-tasks/:id/transition`：领取、转派、开始、完成、失败和取消。
- `POST /billing/charge-items/:id/void`：收银异议作废。
