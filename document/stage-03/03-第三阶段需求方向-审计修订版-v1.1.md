# 1. Stage 03 新定义

Stage 02 已完成大规模业务代码铺开，但源码审计确认基础层尚未完全收口。

Stage 03 不再从“S3.1 直接扩展”开始，而采用四段式：

```text
S3.0 Stage 02 Audit Closure
↓
S3.1 Pilot Ready
↓
S3.2 V1 Commercial
↓
S3.3 Scale & Differentiation
```

总体原则：

1. 安全作用域先于业务扩展；
2. 核心闭环先于功能数量；
3. 国家法规硬要求与行业最佳实践分开；
4. code_complete 不等于 verified；
5. C 端、会员、营销不阻塞 S3.1；
6. 所有 Stage 03 migration 建立在 S3.0 稳定 schema 之上。

# 3. S3.1 — Pilot Ready

## 3.1 合规 P0

### 病历

- 门急诊结束后 24h 归档；
- 住院出院后 3 日归档；
- 归档后直接编辑禁止；
- 特殊修改负责人批准 + amendment；
- 保存不少于 3 年；
- 电子病历身份认证、操作追溯；
- 可靠电子签名 Provider 预留。

### 处方

- 执业兽医备案；
- 签名留样/签章/电子签名备案；
- 当日有效；
- 特殊延长最长 3 天；
- 一式三联；
- 计算机开方满足纸质/可靠电子签名规则；
- 麻醉药单独处方且每张不超过一日量；
- 精神/毒性药单独处方；
- 普通处方保存 >=3 年；
- 麻醉/精神/毒性处方保存 >=5 年。

### 机构

- 许可证号、发证机关、诊疗范围；
- 新版电子证照字段/二维码预留；
- 门店与许可证关联；
- 执业人员备案；
- 公示能力。

### 年报

依据《动物诊疗机构管理办法》第三十条：

- 每年三月底前；
- 上年度诊疗活动；
- 支持生成、导出、提交状态和审计。

### 疫情与废弃物

- 疑似/染疫报告任务；
- 隔离/消毒留痕；
- treatment_restricted；
- 废弃物交接台账。

## 3.2 不作为全国法规硬 P0 的事项

以下转为 P1/可配置质控：

- 普通检验“录入人必须与审核人不同”；
- 所有处方强制第二人复核；
- 所有受控药品双人双锁。

高风险场景可由：

```text
tenant policy
local regulation
hospital SOP
```

升级为强制。

## 3.3 经营 P0

- 日结；
- 对账；
- 审计查询后台；
- 最小回访任务；
- 低库存/近效期。

## 3.4 医疗 P0

- 超时/异常；
- 检验标本；
- 危急值确认；
- 报告引用病历；
- 住院每日病程；
- 出院结算；
- 基础打印。

# 8. 状态规则

仅使用：

```text
not_started
in_development
code_complete
integration_pending
verified
production_ready
```

定义：

- `code_complete`：静态代码、单测、类型、build 满足；
- `integration_pending`：依赖 staging；
- `verified`：migration/RLS/E2E/业务场景均通过；
- `production_ready`：发布检查、配置、安全和回滚准备通过。

任何任务不得因为：

```text
有页面
有 API
有 SQL
有测试文件
```

直接标记 `verified`。
