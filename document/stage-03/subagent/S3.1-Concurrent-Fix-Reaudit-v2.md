# 27. Password Recovery 仍有 Race 风险

Reset 页面当前认为：

``` text
query.type = recovery
OR
query.token
```

即可恢复。

并监听：

``` text
PASSWORD_RECOVERY
```

这是合理的。

但兜底仍依赖：

``` text
session.user.user_metadata.recovery === true
```

这不是一个稳定的 Supabase Recovery Session 判断方式。

Supabase PKCE 回调常见可能是：

``` text
?code=...
```

如果：

``` text
PASSWORD_RECOVERY
```

事件在页面监听注册前已经发生，

当前 fallback 可能将真实 recovery session 判为无效。

### 建议

把 Recovery Intent 放到 Auth Store：

``` text
Auth Callback
↓
识别 recovery
↓
Store recoveryMode=true
↓
Reset Page 消费
```

或正式处理 PKCE：

``` text
exchangeCodeForSession
```

不要依赖：

``` text
user_metadata.recovery
```
