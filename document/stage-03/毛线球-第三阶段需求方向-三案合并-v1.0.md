## 1. Stage 03 的定义与总目标

Stage 01 完成规划，Stage 02 完成代码铺开与基线对齐，Stage 03 的目标是：

**先以合规、可信的方式通过 Stage 02 退出门禁并完成试点，再展开 V1 商业化能力，同时为规模化差异化预留架构。**

对应三个里程碑：

| 里程碑 | 目标 | 关键词 |
|---|---|---|
| S3.1 试点就绪 | 通过退出门禁，医疗主闭环 + 合规 + 日结对账真实可用 | 收口、合规、可验证 |
| S3.2 试点与 V1 商业化 | 在试点医院迭代客户经营、会员、营销、C 端、消息渠道 | 留存、增收、私域 |
| S3.3 规模化与差异化 | AI、设备互联、多渠道、数据仓库等按试点反馈启动 | 差异化、预留兑现 |

三案对"先收口再扩展"的判断完全一致（方案 A 的落地建议、方案 B 21.1、stage-02 v0.5 开发指导），这是合并的基础共识。

## 4. 重点方向合并说明

**监管合规**是 Stage 03 的第一需求方向，三案一致 P0。执行时以方案 B 第 17 章为实现基准（字段、归档、保存、处方、13 项验收），同时落实方案 A 的四项补充：员工档案增加执业兽医资格证书号与备案状态，处方开具权限绑定"已备案"条件；处方笺三联打印进入打印参数体系；机构与兽医信息预留监管平台导出；审计日志保存期不低于 3 年并与病历保存策略对齐。商用前须以农业农村部正式发文（含公告第 734 号）及目标经营地区要求复核。

**客户经营**从"档案记录"升级为"留存运营"。客户 360、合并、分层、流失预警、回访任务构成一个闭环：预警产生回访建议，回访登记结果，报表统计召回转化。注意方案 B 的边界约束：只生成"建议回访"，不自动替代人工医疗判断；营销触达必须先校验营销授权，医疗提醒与营销分离。

**C 端**按裁决结果分两步：S3.1 完成 `customer_identities`、`customer_pet_access`、`customer_consents`、`notification_subscriptions`、`customer_visible` 等模型预留（B 端同步做客户微信绑定状态与 C 端开关配置）；S3.2 启动小程序最小闭环。安全基线执行方案 B §18：客户与员工身份分离、家庭成员授权访问、报告需 published 且 customer_visible、查看下载写审计。

**收费域**在 P0 落日结对账（不可变快照 + 差异登记），P1 落保险理赔材料与费用清单。支付网关仍不强制接入，但外部流水号、幂等键、收银员字段必须齐备，保证未来接网关后对账流程平滑升级。

## 5. 验收与退出标准

**S3.1 退出（试点就绪）** = 方案 B §20 全部门禁 + 方案 B §17.8 十三项合规验收 + E2E 新增场景 J（流失召回闭环）在 staging 可重复执行。未达标准不得标记 production_ready。

**S3.2 退出（V1 商业化）** 在 P1 各方向按方案 B 对应章节验收之外，补充商业指标观察项（来自方案 A 成功指标扩展）：提醒触达后到店转化率、回访完成率、流失客户召回率、优惠券核销率、C 端预约占比、理赔材料输出及时率。

**状态标记规则**：全部采用方案 B 的 6 级枚举；"页面存在"不等于 code_complete，"Mock 数据跑通"不等于 verified。

## 6. 待确认问题

1. 法规复核：《动物诊疗病历管理规范》《兽医处方格式及应用规范》正式文本逐条核对，以及目标经营地区的地方监管差异（责任：业务负责人 + 法务）。
2. C 端形态：微信小程序主体资质（医疗类目审核要求）是否满足；是否需要公众号 H5 兜底。
3. 保险方向：首批对标的保险公司及其理赔材料格式要求（影响 M-06 的导出模板设计）。
4. 审计日志保存期"≥3 年"与财务凭证保存期（对照财税法规）需要租户方确认。
5. 营销费用归属与优惠券预算控制规则（是否 P1 就要预算上限）。
6. 执业兽医备案信息的维护责任归属（医院自维护 + 平台抽查，还是平台审核）。
