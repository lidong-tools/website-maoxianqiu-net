# 3. S31-1-F02 无仓库发药

## 评级

> **PASS**

`dispense_prescription()` 现在明确拆开：

```text
catalog_item_id IS NULL
```

和：

```text
catalog_item_id != NULL
但 warehouse 不存在
```

前者允许作为非库存手工药条目跳过库存。

后者：

```sql
raise exception 'DISPENSE_WAREHOUSE_NOT_FOUND'
```

不会再：

```text
skip inventory
→ prescription = dispensed
```

由于该检查和后续库存扣减、处方状态更新位于同一个 `dispense_prescription()` PostgreSQL RPC 事务中，因此异常会整体回滚。

Hono 也已增加：

```text
DISPENSE_WAREHOUSE_NOT_FOUND
```

错误映射。

上一轮 F02 阻塞关闭。

# 4. S31-1-F03 处方有效期

## 评级

> **PASS（按当前“中国大陆单时区”产品决策）**

当前 `issue_prescription()` 已实现：

```text
p_valid_until <= now()
→ PRESCRIPTION_VALIDITY_IN_PAST
```

以及：

```text
p_valid_until > now() + 3 days
→ VALIDITY_EXCEEDS_MAX
```

PostgreSQL `now()` 在单事务内稳定，因此这里和后续写入：

```text
issued_at = now()
```

保持同一个事务时间基准。

默认有效期：

```text
Asia/Shanghai 当地开具日 23:59:59
```

不再出现上一轮“最长接近 96 小时”的实现。

延长有效期也使用：

```text
issued_at + interval '3 days'
```

作为硬上限。

delivery 文档已经明确：

> 毛线球当前仅服务中国大陆，S3.1 统一使用 `Asia/Shanghai` 作为业务时区，本 Sprint 不宣称 tenant/store timezone 已实现。

在这个产品前提下，可以接受。

# 7. P0：veterinarian registration 当前只有平台管理员能管理，真实医院租户没有可用管理角色

这是本轮剩下的主要阻塞。

当前设计已经明确：

```text
veterinarian registration = tenant-level
```

RLS：

```text
has_permission(
  tenant_id,
  NULL,
  'veterinarian_registration.read'
)
```

这个方向正确。

同时 migration 28 已从：

```text
store_manager
doctor
```

移除：

```text
veterinarian_registration.read
veterinarian_registration.manage
```

这也是正确的，因为这两个角色都是：

```text
scope = store
```

不能冒充 tenant-wide role。

## 问题在于：项目当前根本没有 tenant_owner / tenant_manager 默认角色

静态扫描 migration 01～29：

```text
tenant_owner   = 不存在
tenant_manager = 不存在
```

而 migration 28 现在实际上只给：

```text
system_admin
```

保留备案 read/manage。

但是 S3.0 已经把：

```text
system_admin
```

从 tenant employee role 模型拆成独立：

```text
platform_user_roles
```

因此当前形成：

```text
平台管理员
→ 可以拥有备案权限

普通医院租户：
store_manager → 无
doctor        → 无
其他 store role → 无
tenant_owner / tenant_manager → 根本没创建
```

结果就是：

> **真实医院管理员无法自行维护执业兽医备案。**

而 Sprint 1 的 `issue_prescription()` 又明确要求：

```text
prescriber 必须有 active veterinarian_registration
```

所以真实医院会出现：

```text
医生想开处方
→ 必须先有备案
→ 店长/医生不能维护备案
→ 只能平台方替医院维护
```

这与 Pilot Ready SaaS 的租户自治目标不符。

# 11. P1：执业兽医备案有效日期仍使用数据库 current_date，而不是上海业务日期

虽然处方有效期已经统一为：

```text
Asia/Shanghai
```

但 `issue_prescription()` 检查备案有效性仍然：

```sql
valid_from <= current_date
and (valid_until is null or valid_until >= current_date)
```

`upsert_veterinarian_registration()` 默认 `valid_from` 也使用：

```sql
current_date
```

如果数据库 session timezone 是 UTC，则中国时间：

```text
00:00 ～ 07:59
```

期间可能仍被数据库认为是前一天。

这会出现资格生效/失效边界偏差。

既然本 Sprint 已正式声明中国业务时区，建议统一：

```sql
(now() at time zone 'Asia/Shanghai')::date
```

用于：

```text
registration valid_from / valid_until
```

判断和默认值。

不是架构性问题，但属于合规日期边界，建议在 Sprint 1 一并收掉。
