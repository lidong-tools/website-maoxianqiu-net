# 7. 🟡 discharge_patient 并发同幂等键仍有边缘问题

117 中：

```text
先查询 idempotency record
↓
再 SELECT admission FOR UPDATE
```

如果两个完全并发请求使用同一个 key：

```text
A/B 初始都查不到 record
A 先锁 admission
B 等待
A discharge + 写 idempotency + commit
B 获得 admission
看到 status=discharged
→ ADMISSION_NOT_ADMITTED
```

因此第二个并发请求可能没有得到：

```text
第一次的 idempotent replay result
```

数据不会重复出院，但：

```text
严格幂等响应语义
```

还不完整。

### 建议

在拿到 Admission Lock 后：

```text
再次查询 tenant + idempotency_key
```

如果已有：

```text
直接 replay。
```

### 严重度

```text
P1
```

不阻塞 Source Gate，但 Runtime 并发测试时建议补。
