## 2. 🔴 P0 — `v_cage_rows` 未声明

文件：

```text
supabase/migrations/20260810000120_discharge_patient_replay_after_lock.sql
```

当前 `DECLARE` 只有：

```sql
v_admission public.admissions;
v_cage public.cages;
v_existing jsonb;
v_total_charge numeric(12,2) := 0;
```

后面却执行：

```sql
get diagnostics v_cage_rows = row_count;

if v_cage_rows = 0 then
  ...
end if;
```

PL/pgSQL 变量必须先声明。

### 修复

增加：

```sql
v_cage_rows integer := 0;
```

例如：

```sql
declare
  v_admission public.admissions;
  v_cage public.cages;
  v_existing jsonb;
  v_total_charge numeric(12,2) := 0;
  v_cage_rows integer := 0;
begin
```

修复后当前 Defense-in-Depth 逻辑可以保留。

## 3. ✅ Cage Release 收紧逻辑本身正确

新增条件：

```sql
where id = v_admission.cage_id
  and current_admission_id = p_admission_id;
```

比之前：

```sql
where id = v_admission.cage_id;
```

更安全。

它可以防止历史数据异常情况下：

```text
旧 Admission 仍保存 Cage A
但 Cage A 已被新的 Admission 占用
↓
旧 Admission 出院误把 Cage A 释放
```

当前设计：

```text
0 rows affected
→ RAISE NOTICE
→ 不误释放
```

是合理的。

所以：

```text
业务逻辑：✅
SQL 可执行性：❌ 变量声明遗漏
```
