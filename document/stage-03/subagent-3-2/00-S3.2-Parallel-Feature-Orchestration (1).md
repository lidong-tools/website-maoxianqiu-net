> 项目：毛线球宠物医院 SaaS  
> 阶段：Stage-03 / S3.2 并发功能开发  
> 基线：在 S3.1 Fix Pipeline 仍独立执行的前提下，从当前稳定 Main/Base Commit 创建本批 Feature 分支。  
> 核心原则：**S3.2 Agent 不得修改 S3.1 Fix 正在修复的 IAM、Billing 核心、Clinical 核心、Inventory 核心安全边界。**

# 00 — S3.2 并发功能开发总编排

## 1. 目标

在 S3.1 Fix Pipeline 继续修复安全、权限、Context、医疗状态机、库存/寄养事务完整性的同时，启动一批低冲突、高产品价值的新模块。

本批开发：

| Agent | 模块 | 主要价值 |
|---|---|---|
| S32-A | 数据导入中心 V2 | 降低医院迁移/初始化成本 |
| S32-B | 经营报表与驾驶舱 | 支撑院长/店长经营决策 |
| S32-C | 业务文档与打印中心 V2 | 处方/检验/影像/住院等正式输出 |
| S32-D | 消息通知真实 Provider | 替代 Mock Provider，形成真实提醒能力 |
| S32-E | S3.2 Integrator | 最终合并、冲突处理、质量门 |

# 2. 与 S3.1 Fix Pipeline 的并行边界

S3.1 Fix 正在处理：

```text
IAM
Permission
Tenant / Store Context
Billing / Membership / Approval
Clinical / Imaging / Followup
Inventory / Boarding
RPC ACL
RLS
Security
```

因此 S3.2 Agent 必须遵守：

```text
不能改 Permission Helper
不能改 /api/user/context
不能改 Billing 核心 RPC
不能改 Clinical 核心状态机
不能改 Inventory 核心库存事务
不能改 Boarding 核心事务
```

如确实需要这些能力：

```text
写 Handoff
↓
等 S3.2 Integrator + S3.1 Integrator 最终接入
```

# 8. 跨域 Handoff

所有跨域需求写：

```text
document/s32-handoff/
```

命名：

```text
S32-A-HANDOFF.md
...
S32-D-HANDOFF.md
```

内容至少：

```text
目标业务
需要调用的其他 Domain
输入
输出
失败策略
事务要求
权限
是否需要 Audit
```
