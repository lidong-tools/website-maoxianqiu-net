# 15. 风险：PostgREST Row Limit

Supabase/PostgREST 通常会有单次返回行数限制。

当医院数据超过一定规模：

``` text

```

``` text

```

不会报错，

最终会出现最危险的 BI 问题：

> **数字看起来正常，但其实少算。**

# 44. 🔴 Messaging P0 --- Retry 可能重复发送外部消息

当前：

``` text
retryDelivery()
```

流程：

``` text
读取 delivery.attempts
↓
attemptNo = attempts + 1
↓
provider.send()
↓
发送成功/失败
↓
insert attempt record
```

也就是说：

> **外部副作用先发生，数据库 Claim 后发生。**

------------------------------------------------------------------------

# 45. 并发场景

两个请求同时：

``` text
Retry
```

都读到：

``` text
attempts = 1
```

两边都认为：

``` text
attemptNo = 2
```

然后：

``` text
请求 A → SendGrid send
请求 B → SendGrid send
```

两封邮件都已经发出。

之后数据库：

``` text
unique(delivery_id, attempt_no)
```

可能让第二次 Attempt Insert 失败。

但：

> **数据库冲突发生时，第二封邮件已经发出，无法撤回。**

------------------------------------------------------------------------

# 46. 正确 Retry 模型

先在数据库：

``` text
Claim Attempt
```

成功后才调用 Provider。

例如：

``` text
BEGIN

lock delivery

if attempts >= max:
  reject

insert attempt:
status = sending
attempt_no = next

COMMIT
```

只有成功获得 Attempt：

``` text
才执行 Provider Side Effect
```

完成后：

``` text
update attempt/result
update delivery
```

或者采用：

``` text
Outbox Job
```

模型。
