# 毛线球 Stage-03 / S3.1 并发任务 C
## 医疗闭环增强（Nurse / Lab / Inpatient / Discharge）

> 角色：开发员工 C  
> 目标：补齐医生开立医疗行为后的执行、检验、住院和出院闭环。  
> 完成状态只能写 `code_complete / integration_pending`。

## 1. 严格边界
只负责：护士任务自动生成与超时异常、检验标本、危急值、Lab→Medical Record 引用、住院每日病程、出院结算、相关打印补强。

不要重做：病历 archive/amendment、处方有效期/发药事务、兽医备案、tenant init、日结/对账、regulatory。

## 2. Migration
独占 `44~49`。禁止修改 `01~43` 和使用 `50+`。

## 3. Nurse Task
医生创建注射/输液/治疗/处置/护理医嘱后自动生成 nurse task。

必须包含：source_type/source_id、scheduled_at、assignee、status，并保证 source 幂等。

状态：`pending / in_progress / completed / failed / cancelled`，支持 overdue/due soon/exception。

source 取消：未执行 task → cancel；已执行 task → 永久保留。

## 4. Lab Samples
建议 `lab_samples`：lab_order_id、sample_no、sample_type、collected/received/rejected 信息。

状态：`planned / collected / received / testing / completed / rejected`。

## 5. Critical Value
lab result 支持：is_critical、critical_value_code、notified/acknowledged 信息。

流程：`critical → notify → acknowledge → audit`。

普通检验“双人审核”只能做 tenant policy，不得写成全国强制法规。

## 6. Lab → Medical Record
引用已发布检验结果时必须保留 `source_lab_result_id`，不得只复制文本。

## 7. Inpatient Progress
建议 `inpatient_progress_notes`：admission_id、record_date、author、content、status、signed_at。每天允许多条。

## 8. Discharge
流程：`prepare discharge → calculate charges → pending settlement → payment → discharge → archive deadline`。

正常未结算不可 discharge；特殊免结算必须 permission + reason + audit。

## 9. 原子性
complete nurse task、ack critical、sign progress、prepare/finalize discharge、waive settlement 等高风险动作走 Hono + transactional RPC。

涉及 billing/discharge 不要拼多个独立 RPC。

## 10. 权限
至少 nurse_task、lab_sample、lab_critical、inpatient_progress、inpatient_discharge 各自 read/write/execute 类权限，继续 tenant/store scope。

## 11. Audit
覆盖 nurse task、sample、critical value、progress sign、discharge prepare/finalize/waive。

## 12. UI
尽量复用现有 clinical/diagnostics/inpatient 目录与组件；不得正常业务手填 UUID。

打印只补 Pilot 必需 discharge summary，并检查 lab report/medical record 基础信息。

## 13. 测试
覆盖：nurse source 幂等、source cancel、sample transition、critical ack、lab source reference、progress sign、cross-tenant admission、unsettled discharge fail、settled pass、waive reason+permission、archive deadline。

建议：`medical_loop_s3_1.sql`。

## 14. Shared Files
manifest、router/menu、permission seed、components.d.ts 只 append。不要改 current docs。

## 15. 完成标准
`Medical Loop Enhancement = code_complete`，`runtime = integration_pending`。

且：无跨 tenant/store、无 UUID 手输、状态机不可逆乱跳、关键 Command 原子、audit 完整。

## 16. 交付
branch、HEAD SHA、commit list、migrations 44~49、schema、RPC/API、UI、permissions、audit、tests、manifest/lint/typecheck/build 原始输出、known issues、CONFLICT_PRONE_FILES。

完成后停止。
