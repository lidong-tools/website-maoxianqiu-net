## 0. 背景与范围

两份前置审查（`document/三阶段需求遗漏与一致性审查.md`、`document/行业需求对标与遗漏分析.md`）发现毛线球需求存在三类遗漏：

1. **合规红线遗漏**：现行 §17 合规专章覆盖病历保存、电子签名预留、审计，但《动物诊疗机构管理办法》《动物诊疗病历管理规范》、四川省 2025-08 通知、农业农村部 734 号公告要求的多条强制项未建模。
2. **行业标配缺口**：宠主端门户、在线问诊、LIS 设备直连、私域营销、宠物保险、中心药房等竞品标配能力缺失。
3. **运营增强缺口**：排班考勤、设备全生命周期、手术模块、ICU 白板、收费自动捕获、投诉、培训、院长移动看板。

本方案按 P0（合规红线，验收前必决）/ P1（行业标配，V1 商业增强）/ P2（运营增强）分级给出可落地需求。已明确"有意排除"的项（DICOM PACS、设备直控、AI 自动诊断、保险直连结算、自建在线问诊平台、自建 B2B 供应链商城）不在本方案新建，仅在"生态对接预留"中说明。

## 1. P0：合规红线补强（验收前必须完成）

> 目标：将 PRD §17 合规专章逐条对齐监管条款，建立"法规条款 → 系统能力"映射。以下 7 项均为法规强制，缺失将导致上线/验收风险。

### 1.1 诊疗废弃物处置管理

- **依据**：《动物诊疗机构管理办法》§26、《医疗废物管理条例》、四川省 2025-08 通知"规范诊疗废弃物处置"。
- **核心需求**：
  - 建立 `medical_waste_records`：废弃物类型（染疫动物及其排泄物、污染物、动物病理组织、锐器、药瓶等）、重量/数量、交接人、接收处理机构、交接时间、转运联单号。
  - 支持按"签约专业处理机构"登记，禁止随意丢弃；排放未经无害化处理的诊疗废水需记录。
  - 与诊疗活动关联（如手术、住院、化验产生的废弃物）。
- **字段要点**：`waste_type`、`quantity`、`handler_employee_id`、`disposal_org`、`handover_at`、`manifest_no`、`store_id`、`tenant_id`。
- **验收**：可生成废弃物交接台账并按期导出；审计记录创建/修改。

### 1.2 疫情 / 染疫上报

- **依据**：《动物诊疗机构管理办法》§25（发现染疫或疑似染疫立即上报，隔离消毒，不得擅治应扑杀疫病）。
- **核心需求**：
  - 新增"传染病上报"工作流：宠物风险标签含 `infectious`（PRD §294 已有），当就诊/检验标记为疑似染疫时，触发上报任务。
  - 记录上报动作（向农业农村主管部门 / 动物疫病预防控制机构）、上报时间、隔离消毒措施、是否疑似应扑杀疫病（拦截擅治）。
  - 不替代官方渠道，但系统须留痕并提醒责任人。
- **状态机**：`detected → reported → isolated → resolved/customed`（应扑杀疫病进入 `customed_blocked` 禁止治疗）。
- **验收**：疑似染疫宠物生成上报任务并可标记隔离措施；应扑杀疫病拦截治疗并告警。

### 1.3 毒麻 / 精神 / 毒性药品专项管控

- **依据**：农业农村部 734 号公告、兽药管理条例、四川省 2025-08 通知"规范用药管理"。
- **现状**：PRD §759 仅规定"兽用麻醉/精神/毒性药品处方至少保存 5 年"，**无管控流程**——属关键遗漏。
- **核心需求**：
  - `catalog_items` / 库存增加 `is_controlled_drug` 标记与受控级别（麻醉/精神/毒性）。
  - 受控药品采购、入库、保管实行**双人双锁 / 双签**流程；发放需双人核对。
  - 空瓶 / 安瓿回收登记，与发药量对账。
  - 处方关联 `controlled_drug` 权限码（承接 ADR-MED-001），发药须二次确认并审计。
- **字段要点**：`is_controlled_drug`、`controlled_class`、`empty_vial_returned`、`double_check_by_employee_id`。
- **验收**：受控药品无双人核对无法发药；空瓶回收可对账；处方保存期按 §759 执行。

### 1.4 执业兽医师签名留样与电子签章备案

- **依据**：734 号公告"执业兽医师在备案单位签名留样或者专用签章、电子签名备案后，方可开具处方"。
- **现状**：PRD §17 仅"执业兽医备案门禁"，未建模签名留样 / 电子签章备案流程。
- **核心需求**：
  - 员工档案增加 `signature_specimen_ref`（手写签名留样扫描件）与 `e_signature_registration`（电子签章/电子签名备案号、备案机构、备案时间）。
  - 处方开具前置校验：该执业兽医师须已完成签名留样或电子签章备案，否则禁止开方。
  - 承接 §17.5 可靠电子签名 Provider 接入：备案号与 `signature_provider / signature_transaction_id` 关联。
- **验收**：未备案签名/签章的执业兽医师无法开具处方；备案信息可查可审计。

### 1.5 动物诊疗许可证生命周期管理

- **依据**：《动物诊疗机构管理办法》§13-§17（分支另办证、名称/法人变更、许可证公示、从业人员公示、监督电话公示）。
- **核心需求**：
  - 机构主数据增加 `practice_license`：许可证号、发证机关、诊疗活动范围、有效期限、公示状态。
  - 门店（store）与许可证绑定；兼营美容/寄养的须记录独立区域设置（§21 兼营独立区域）。
  - 分支门店提示"需另行办理许可证"；许可证临近到期提醒。
  - 前台公示组件：许可证 + 执业兽医资格 + 监督电话（可配置展示）。
- **验收**：门店可维护许可证信息并触发到期提醒；公示组件可渲染。

### 1.6 年度活动报告

- **依据**：《动物诊疗机构管理办法》§27、四川省 2025-08 通知"规范年度报告"。
- **核心需求**：
  - 提供年度活动报告生成器：汇总本年度诊疗量、处方量、受控药品使用、疫情上报、废弃物处置、员工备案等，形成可提交报告。
  - 报告按 tenant/store 维度生成，支持导出与提交状态记录。
- **验收**：可一键生成年度合规报告并留痕。

### 1.7 检验 / 处方双重审核（用药安全）

- **依据**：蘑菇宠医"处方双重审核（循证、防重复用药/配伍禁忌/超疗程/过度抗菌）"实践；用药安全合规趋势。
- **现状**：PRD 检验状态机不校验"录入人≠审核人"；处方无独立审核环节。
- **核心需求**：
  - 检验报告发布前强制"录入人与审核人不得为同一人"（关闭 ADR-MED-003 悬空决策）。
  - 处方提交时增加用药安全检查：重复用药、配伍禁忌、超疗程、过度抗菌提示（承接三案合并裁决 5 的"用药安全规则校验"列为 P1 处方提交检查）。
  - 高危处方可配置需第二人复核。
- **验收**：同人录入+审核被拦截；处方提交触发用药安全检查规则。

## 2. P1：客户与增长能力（行业标配，V1 商业增强）

### 2.1 宠主端小程序 / 客户门户（扩充 §18）

- **依据**：小暖 App、微宠医/蘑菇宠医小程序、全球 client portal（Digitail/Shepherd）。
- **现状**：§18 仅预留数据模型，C 端降为 P1。
- **核心需求**：在 §18 数据模型基础上，明确首版门户能力：在线预约、报告查看（published + customer_visible）、疫苗/驱虫/复诊提醒、会员/储值余额、健康档案摘要、消息中心。
- **范围**：微信小程序/公众号优先；安全规则沿用 §18 安全要求。

### 2.2 在线问诊生态对接（非自建）

- **依据**：小暖/微宠医/蘑菇宠医均提供线上问诊；本方案不新建问诊平台（阶段3 明确排除），但需"生态对接预留"。
- **核心需求**：定义问诊工单 ↔ 门诊就诊的转诊接口与数据映射（问诊结论可作为就诊主诉预填），不内置视频/诊断能力；由合作方提供问诊，毛线球承接线下转化与病历归档。
- **范围**：预留 `teleconsult_ref` 关联字段；不做自动开方。

### 2.3 LIS 化验设备直连

- **依据**：小暖已连接 2300 台化验设备；全球 IDEXX VetConnect PLUS。
- **现状**：PRD 检验仅有"外送检验工作流"，无设备直连。
- **核心需求**：定义 LIS 集成适配层——分析仪结果自动回传检验单（标本号/结果/参考范围/异常标记），减少手工录入；支持主流仪器协议适配（HL7/厂商 API）。
- **范围**：P1 先定义适配接口与 1-2 个主流仪器对接，不承诺全品牌覆盖。

### 2.4 私域营销引擎

- **依据**：小暖微信系统（会员卡/积分商城/优惠券/处方粮复购/健康提醒）、微宠医处方粮复购。
- **现状**：会员/储值/积分/套餐已有（P1）；消息模块退出 MVP（方案 A）；营销引擎列为 P1（市场调研 M-07）。
- **核心需求**：在消息模板与会员体系之上，提供营销活动管理（优惠券/满减/套餐包）、企微/社群触达占位、复购提醒（处方粮/驱虫/疫苗）、客户分层人群包。
- **范围**：内容生产与触达合规（短信/微信需真实 Provider，承接方案 A）。

### 2.5 宠物保险对接

- **依据**：小暖与中国人保/众安合作。
- **现状**：保险理赔材料 P1 预留，不直连结算（明确排除）。
- **核心需求**：定义理赔材料导出包（病历/处方/发票/检验结构化），供保险方调取；预留 `insurance_claim_ref`；不内置核保/直连结算。

### 2.6 中心药房 / 供应链集采（连锁）

- **依据**：小暖中心药房 + 药品牌照模式。
- **核心需求**：支持"总部中心药房 → 门店调拨"的连锁供应链；供应商集采与统一定价；门店库存与中心药房库存联动。
- **范围**：复用 §12 采购库存与跨店调拨，新增中心药房角色与统采流程。

- **竞品**：小暖（CRM/化验室设备连接/线上问诊/微信营销/中心药房/保险）、微宠医（处方粮/在线问诊/健康提醒）、蘑菇宠医（在线问诊双重审核/线上购药）；全球 IDEXX VetConnect（LIS）、SmartFlow（ICU 白板）、Shepherd/Digitail（client portal + AI）、ezyVet（100+ 集成）。
- **前置审查**：`document/三阶段需求遗漏与一致性审查.md`、`document/行业需求对标与遗漏分析.md`。
