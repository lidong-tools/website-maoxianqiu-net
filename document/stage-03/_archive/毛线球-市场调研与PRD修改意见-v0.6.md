# 【毛线球】PRD 修改意见（基于真实市场调研）

> 版本：v0.6（修改意见稿，待评审）
> 日期：2026-08-07
> 针对文档：`stage-01-plan/01-产品需求说明书-PRD.md`（v0.4）
> 调研方式：公开网络调研（行业报告摘要、竞品公开资料、宠物 SaaS 行业分析、农业农村部法规文件、医院经营与私域运营实践文章），来源清单见文末第 6 节。
> 本文只提出"需求层面"的修改意见，不改变 PRD 已确认的技术栈与实现约束。每条意见标注优先级：
>
> - P0：不改会造成合规风险或明显脱离市场，建议在下一版 PRD（v0.5）必须纳入
> - P1：显著影响产品竞争力，建议纳入 V1 范围或明确排期
> - P2：市场趋势明确但时机未到，建议在 PRD 中写明预留设计，不进入首版开发

## 1. 市场调研结论摘要

### 1.1 行业背景

中国宠物医疗市场持续增长，连锁化扩张加速，行业报告普遍把"数字化运营体系构建"列为连锁机构的核心能力建设项。对管理系统厂商而言，市场已从"有没有系统"进入"系统能不能支撑连锁化、合规化和客户经营"的阶段。

### 1.2 竞争格局

公开资料显示当前宠物 SaaS 市场仍处于教育期，没有绝对领头羊，主要玩家各有侧重：

| 竞品 | 定位与特点 |
|---|---|
| 宠老板 | 收银、进销存、预约、会员等门店管理，配合内容与社群服务店主 |
| 宠知道 | 内容引流转 SaaS+B2B，提供代运营式经营支持 |
| 坚果宠物 | ERP+CRM 软硬件一体机，探索连锁化管理 |
| 蜗牛小店 | 判断店主更关注营销而非效率，主打海报、刮刮卡、体检报告等营销工具 |
| 海际它品 | 工厂—门店 B2B 直供供应链 |
| 杏聆荟等医院向系统 | 强调全流程数字化、精细化数据、病历与会员一体化 |

行业总结的门店痛点是"获客难、管理难、信息化程度低"，厂商普遍转向"B 端赋能"：营销工具、社群运营、供应链直供、代运营和连锁化支持。

**对毛线球的含义**：纯"管理效率型"系统差异化不足。毛线球的医疗深度（病历、处方、检验状态机、多租户隔离）是多数竞品不具备的优势，应守住；但"客户经营 + 合规"两块市场刚需目前在 PRD 中覆盖不足。

### 1.3 B 端（医院经营者）真实需求

综合经营类文章与系统推荐文章，B 端高频需求按出现频率排序：

1. **客户留存与召回**：建立完整生命周期档案的机构客户主动复诊率显著提升；智能提醒被普遍引用为降低流失率、提升复购频次的手段；分层运营、流失预警（消费周期、到店间隔、价格敏感度变化）是成熟期机构标配。典型痛点表述是"客户做完绝育就失联"，缺少有效的唤醒机制。
2. **预约叫号与前台效率**：手工登记耗时、排队混乱是前台第一痛点。
3. **收银与对账**：收银对账麻烦、收款方式多、需要按支付方式日结对账。
4. **报表与多店数据汇总**：连锁机构需要统一客户池、各店经营汇总、业绩归属与分账。
5. **营销工具**：多项行业分析指出店主对营销工具的关注度高于纯效率工具；优惠券、储值、拼团、分销、老带新是常见玩法。
6. **AI 提效**：AI 生成病历（语音转写/自动整理）、医嘱辅助生成、用药风险提示、智能回访被 2026 年的行业文章列为升级方向；诊断辅助类 AI 仍以"医生确认"为前提。

### 1.4 C 端（宠主）需求

2026 年宠物门店/医院小程序方案测评与私域运营文章反映的 C 端刚需：

1. 微信生态是绝对主阵地：小程序 + 公众号双端，承载在线预约、报告查询、疫苗驱虫记录、会员储值、提醒订阅。
2. 一主多宠的宠物档案、服务记录查询。
3. 诊疗类业务对隐私与合规敏感（病历、报告需授权查看）。
4. 连锁场景要求：门店独立库存、到店核销、导购归属、业绩统计、自动分账、总部数据汇总。

**对毛线球的含义**：PRD v0.4 中消息触达只有"模板 + 发送记录 + 供应商适配层"，没有定义任何 C 端承载端；客户自助被放在 V1.5。这与市场现状明显脱节——竞品的 C 端小程序已是标配。

### 1.5 监管合规趋势（关键发现）

这是本次调研中对 PRD 影响最大的部分，PRD v0.4 基本未覆盖：

1. 农业农村部已制定《动物诊疗病历管理规范》并修订兽医处方管理相关规定：
   - 门（急）诊病历在诊疗完成后 24 小时内归档，住院病历在动物出院后 3 日内归档；
   - 病历至少保存 3 年，期满销毁需机构负责人批准并留存记录；
   - 兽医处方只对应一次诊疗的用药需求，原则上当日有效，最长不超过三天；
   - 处方笺一式三联（前记、正文、后记）；麻醉药品单独开具且不超一日量；
   - 普通处方保存 3 年以上，麻醉、精神、毒性药品处方至少保存 5 年；
   - 电子病历需达到纸质病历要求，系统需具备身份识别、权限控制、操作追溯能力；可靠电子签名与手写签名具有同等法律效力；计算机开方应一并输出纸质处方。
2. 农业农村部 2025 年 7 月《关于加强动物诊疗管理工作的通知》：
   - 启用新版动物诊疗许可电子证照；
   - 要求 2025 年 11 月 30 日前将机构和兽医数据全部纳入信息平台管理并动态维护；
   - 强调执业兽医备案"应备尽备"、处方开具规范、年度报告制度。
3. 中国兽医协会等行业组织持续推动"病历处方合规化"倡议，多地已有因病历处方不规范被行政处罚的公开案例。

**对毛线球的含义**：合规不是加分项，是宠物医疗 SaaS 的准入项。一套能帮助医院满足病历归档时限、保存年限、处方有效期、执业兽医备案管理的系统，本身就是卖点。PRD 需要新增合规章节，并将保存年限等法定要求写入数据可靠性约束。

### 1.6 其他趋势

1. **宠物保险与医险联动**：众安、京东等推动"保险 + 科技 + 服务"，行业出现"医险联动诊疗规范"与价格透明化讨论。医院端需求是能够输出标准化的理赔材料（诊断证明、费用明细、影像报告），而非自建保险结算。
2. **在线问诊常态化**：京东健康、市宠云医等 24 小时互联网宠物医院已上线，视频问诊被行业文章列为常态化趋势。对单体医院系统是合作接入需求，不是自建需求。
3. **设备互联**：检验影像设备结果自动回传（LIS/PACS 轻量对接）是连锁和专科医院的升级需求。

## 3. 逐条修改意见

### M-01（P0）新增"监管合规"章节

**现状**：PRD 第 10、11 章定义了病历版本与处方状态机，但只从"业务正确"出发：病历只定义了 draft/signed/revised，处方没有有效期概念，员工模型没有执业兽医资质字段，数据可靠性（24.4）没有法定保存期限，病历签署仅定义为系统内动作、未考虑电子签名法律效力。

**市场依据**：《动物诊疗病历管理规范》及兽医处方管理修订规定、农业农村部 2025 年 7 月加强动物诊疗管理工作通知（详见 1.5 节）。多地已有病历处方不规范的行政处罚案例。

**修改建议**：

1. 新增独立章节"监管合规"（建议作为第 36 章，或并入第 10 章下新增 10.5），内容包括：
   - **病历归档时限**：门（急）诊病历在诊疗完成后 24 小时内完成归档检查，住院病历在出院后 3 日内归档。系统需要提供"逾期未归档"清单和提醒（进入工作台待办）。
   - **病历保存期限**：病历自归档起保存不少于 3 年；期满销毁必须由机构负责人（租户管理员/店长角色）批准，销毁动作写入审计日志并留存销毁记录。与 21 章文件延迟清理机制对齐：医疗文件清理任务必须校验保存期限。
   - **病历编号**：机构内病历号规则可配置（对应"使用规范病历并建立病历号"的要求），与 24.4"业务单号可读"已有原则复用。
   - **处方有效期**：处方提交后原则上当日有效，租户可配置延长，最长不超过 3 天；超期处方状态机新增 `expired` 分支（submitted -> expired），药房发药 Command 校验有效期。
   - **处方打印**：处方笺支持三联打印模板（前记：机构与宠主宠物信息；正文：药品、规格、数量、用法用量；后记：医师签名、金额），计算机开方必须能输出纸质处方；纳入 27.1.3 打印参数体系。
   - **特殊药品**：目录项目（14.3 药品字段）新增"特殊药品类别：无/麻醉/精神/毒性"属性；麻醉药品处方单独开具、单次不超一日量；麻醉、精神、毒性药品处方保存不少于 5 年；开具需要独立权限码（如 `prescription.special_drug.create`），与 5.3 权限模型一致。
   - **执业兽医备案**：员工档案（19.2）新增字段：执业兽医资格证书号、执业备案状态、备案机构、签名样本/电子印章备案状态。医生角色的处方开具权限必须以"已执业备案"为前提条件（权限 + 数据条件双重校验，与 34 章按钮可用性原则一致）。
   - **监管数据报送（预留）**：预留机构信息、执业兽医信息、诊疗许可电子证照字段的导出/对接能力，用于对接农业农村部门信息平台；首版只需保证数据完整可导出，不做自动对接。
2. 第 5.2 节角色表"医生"行补充：处方权依赖执业备案状态。
3. 第 10.3 节补充：签署后的电子病历需具备身份识别、权限控制、操作追溯能力（现有审计体系已满足大部分，需要显式声明以满足法规表述）。

**影响范围**：数据模型（员工资质、处方有效期、特殊药品属性）、状态机（处方 expired）、打印模板、权限矩阵、报表（逾期归档清单）。

### M-02（P0）文档解释规则加入"法规红线优先"

**现状**：PRD 第 0 节冲突优先级为"已确认业务决策与 ADR > PRD > 数据模型 > UI/API > 旧系统手册"。

**修改建议**：在冲突规则最前加入一条：农业农村部门法规、强制性合规要求（如病历保存年限、处方有效期）优先于一切业务决策与 ADR。业务决策可以在法规要求之上加严（如保存更久），不可放松。

**理由**：避免出现"为了业务方便把病历保存期调短"这类在评审中难以反驳的决策。

---

### M-03（P0）C 端触点提前到 V1

**现状**：PRD 3.3 节将"客户自助"排除在首版核心之外（隐含 V1.5）；第 18 章消息触达只定义了模板、触发场景和发送记录，没有定义任何客户侧承载端。

**市场依据**：1.4 节。微信生态（小程序 + 公众号）承载在线预约、报告查询、疫苗记录、会员储值已是竞品标配；私域运营文章普遍以微信为唯一阵地。

**修改建议**：

1. 第 3.2 节 V1 范围新增第 11 项："C 端触点：微信小程序（或公众号 H5）最小闭环"，最小能力定义为：
   - 客户微信账号绑定（openid/unionid 与客户主档关联，一个客户可绑定多人照护同一宠物）；
   - 在线预约与改期（复用第 9 章预约状态机，C 端发起的预约进入 `draft/confirmed`，门店确认）；
   - 疫苗/驱虫记录与下次提醒查看（复用 29 章数据，只读）；
   - 检验报告查看（复用 12 章发布后报告，受控访问，查看行为写审计日志，与跨店查看医疗记录同一原则）；
   - 提醒订阅与营销授权管理（对接 7.1 营销授权状态字段，客户可自助关闭营销触达，医疗提醒与营销授权分离的原则已在 29.4 存在，C 端需要提供开关入口）；
   - 会员/储值余额与消费记录查看。
2. 第 18 章补充：消息渠道优先落地微信订阅消息/模板消息适配器（而非只做"留适配层"），短信保留。
3. 商城、分销、拼团等交易型 C 端能力仍留在 V1.5，本次不提前。
4. B 端配套要求（影响 08-页面级需求）：客户详情新增"微信绑定状态"；门店参数中心（27 章）新增 C 端开关（是否开放在线预约、是否开放报告查看）。

**理由**：提醒触达如果只落到短信，触达率和成本都无法与微信竞争；没有 C 端承载，"复诊提醒""客户自助"的价值闭环不成立。

### M-04（P0）客户流失预警、分层与回访任务

**现状**：第 7 章客户管理有档案、合并、360 视图和标签，但没有生命周期状态、流失预警、回访任务。提醒（18.2）全部是"事件触发型"（疫苗、复诊、生日），没有"流失挽回型"。

**市场依据**：1.3 节。"客户做完绝育就失联"是高频痛点；生命周期档案、智能提醒、分层运营、流失预警被多篇文章引用为留存体系的核心，并给出正向效果数据（复诊率、流失率、复购频次的改善）。

**修改建议**：

1. 第 7 章新增 7.3"客户生命周期与流失预警"：
   - 生命周期状态由系统计算：新客、活跃、沉默、流失（阈值租户可配，如 180 天未到店为沉默、365 天为流失）；
   - 流失预警规则：到店间隔显著超过该客户历史周期、提醒触达后未响应、储值余额长期未消费；预警进入门店工作台（6.1）待办；
   - 客户分层：在现有标签之上增加系统分群维度（物种、消费频次、消费金额区间、会员等级），供消息触达（18 章）按分群选择接收人。
2. 新增 7.4"回访任务"：
   - 触发来源：流失预警、术后/出院随访计划（关联住院 discharge）、医生在病历中下达回访医嘱；
   - 任务字段：客户、宠物、关联就诊、负责人、计划时间、回访方式、结果、备注；
   - 状态机：pending -> in_progress -> completed / skipped / cancelled（复用 09 文档护理任务状态机风格）；
   - 回访结果登记进入客户沟通记录（7.2 已有沟通记录 Tab）。
3. 第 20.1 节 MVP 报表补充：客户流失与召回统计（流失数、召回数、回访完成率）。
4. 第 26 节成功指标补充：提醒触达后到店转化率、回访完成率（现有"提醒触达率"保留）。

### M-05（P1）收银对账流程

**现状**：16.2 节"首版可先记录支付，不必接支付网关"。该决策本身合理，但缺少对账环节：门店实际经营中现金、微信、支付宝、储值混用，日结对账是收银台的日常刚需（竞品收银模块均含日结）。

**修改建议**：

1. 16 章新增 16.5"收银对账"：
   - 日结单：按门店 + 收银台 + 营业日汇总各支付方式应收/实收，支持收银员交接（班次）；
   - 对账差异：外部支付流水号与本地收款核对，差异登记（长款/短款）并进入财务待办；
   - 首版不接网关时，对账以"人工录入外部流水汇总 + 系统收款记录"比对方式进行，数据模型不变（外部流水号字段已存在）。
2. 20.1 节报表新增"日结对账表"。
3. 支付网关接入后，对账流程升级为自动比对，接口预留。

### M-06（P1）保险理赔材料与价格透明

**现状**：3.3 节排除"真实医保或人医医保结算"，合理；但完全没有涉及商业宠物保险场景。

**市场依据**：1.6 节。众安等保险商推动"保险 + 科技 + 服务"生态，行业出现医险联动诊疗规范与价格透明化讨论；医院端的现实需求是出具理赔材料，不是自建结算。

**修改建议**：

1. 21 章新增"理赔材料包"能力：按就诊聚合导出诊断证明、费用明细清单、检验/影像报告、病历摘要（经授权）为 PDF 包，供宠主向保险公司提交；导出动作写审计日志。
2. 16 章收费单补充"费用清单打印"（逐项列明项目、单价、数量、折扣、实收），对应价格透明化趋势，复用打印参数体系。
3. 3.3 节排除项注记修改：不做保险直连结算，但保留"理赔材料输出"；未来保险公司 API 对接为预留方向。
4. 理赔材料中的病历摘要输出需遵循 M-01 的病历查阅授权原则（未经诊疗授权不得查阅）。

### M-07（P1）基础营销引擎纳入 V1

**现状**：17 章会员/储值/套餐整体在 V1；营销活动和积分玩法实际上被推到了 V1.5 之外（18 章只有消息）。

**市场依据**：行业分析明确"店主更关注营销而非效率"（蜗牛小店结论）；私域运营文章把优惠券、储值、老带新作为基础玩法。营销工具是 B 端付费意愿最强的模块之一。

**修改建议**：

1. 3.2 节 V1 范围新增"基础营销引擎"，限定三个最小能力：
   - 优惠券：模板（满减/折扣/指定项目）、定向发放（按 7.3 分群）、核销（收费单抵扣）、费用归属、有效期与防叠加规则（与 27.1.1 计价参数的折扣叠加规则联动）；
   - 老带新：推荐关系登记（新客创建时记录推荐人）、奖励发放（储值金或优惠券）、奖励上限；
   - 生日营销：宠物生日/客户生日触达（18.2 已有生日提醒，补充营销动作与优惠券发放）。
2. 拼团、秒杀、分销、社区团购保持 V1.5 不变。
3. 与合规相关的边界：营销触达必须先校验营销授权状态（7.1 已有字段），医疗提醒与营销分离原则（29.4）继续适用。

### M-08（P1）AI 辅助书写（不改变"不做 AI 诊断"的排除项）

**现状**：3.3 节排除"AI 自动诊断"。10、11 章病历与处方编辑没有效率工具规划（只有模板）。

**市场依据**：2026 年行业文章把"AI scribes 自动生成病历""医嘱内容智能生成""用药风险提示""智能回访"列为医院数字化升级方向；医生写病历耗时是明确的效率痛点。

**修改建议**：

1. 3.3 节排除项注记细化：排除的是"AI 自动诊断/替代医生决策"，不排除 AI 辅助书写类能力。
2. V1 增强项新增：
   - 病历语音/文本转写整理：医生口述或粗输入，AI 整理为 SOAP 结构草稿，明确标注"AI 生成，待医生确认"，未经确认不得进入签署流程；
   - 用药规则提示（规则库优先，不依赖 AI）：配伍禁忌、物种禁忌、剂量范围校验，在处方提交时提示（与 11.1 皮试/特殊提示字段同源扩展）；
   - 智能回访话术建议（服务于 M-04 回访任务）。
3. 所有 AI 生成内容必须可追溯：记录生成来源、模型标识、确认医生与确认时间（进入审计字段体系）。
4. 实现方式约束：AI 调用必须走 Hono 服务端，不在前端直接持有第三方密钥（与 24.3 安全原则一致）。

### M-09（P2）在线问诊仅预留

**市场依据**：京东健康、市宠云医等互联网宠物医院已上线，视频问诊趋势明确；但对毛线球目标客群（医院侧管理系统）而言，自建问诊平台不经济，更可能是与第三方互联网医院合作。

**修改建议**：在 PRD 增加一条预留说明：就诊主记录（10.1）预留"就诊渠道：到店/线上"字段与远程咨询记录挂载点，不建设问诊流程、不做医生端视频能力。若未来合作接入，第三方问诊结果以附件和摘要形式归档到病历。

---

### M-10（P2）设备互联预留

**市场依据**：检验影像设备结果自动回传是连锁与专科医院升级需求；PRD 27.1.4 已明确首版不做硬件即插即用，方向正确。

**修改建议**：12 章补充一句预留设计：检验/影像结果录入 API 按"可被外部系统调用"设计（鉴权、幂等、审计），为未来 LIS/PACS 轻量对接保留通道；不做 DICOM。

---

### M-11（P2）供应链深化仅预留

**市场依据**：海际它品的 B2B 直供、连锁分账模式存在，但属于平台型业务，与毛线球当前定位不符。

**修改建议**：维持 3.3 排除项不变；在 15 章补一句：采购单据模型保留供应商平台对接字段预留；C 端商城分账（连锁导购归属、自动分账）在 V1.5 商城规划时再评估。

### M-12（P0）数据可靠性补充法定保存基线与电子签名

**现状**：24.4 节有时间、金额、单号、事务等约束，无保存期限基线，无电子签名表述。

**修改建议**：

1. 24.4 节新增"法定保存基线"表：

   | 数据 | 最低保存期限 | 依据 |
   |---|---|---|
   | 门（急）诊/住院病历 | 3 年 | 动物诊疗病历管理规范 |
   | 普通处方 | 3 年 | 兽医处方管理规定 |
   | 麻醉/精神/毒性药品处方 | 5 年 | 兽医处方管理规定 |
   | 审计日志 | 3 年（建议与病历对齐） | 合规追溯需要 |
   | 财务收款/退款记录 | 按财税要求（另行确认，不低于 5 年） | 财税法规 |

2. 补充：归档数据的删除/销毁必须是显式审批流程（租户管理员批准 + 审计记录），禁止级联物理删除；与"客户/宠物仅软删除"的既有原则一致并扩展为全局数据生命周期策略。
3. 补充：病历与处方签署预留"可靠电子签名"（第三方 CA/电子签服务）对接点；首版系统内签署动作满足基本追溯，电子签为增强项。法规依据：可靠电子签名与手写签名具有同等法律效力。

### M-13（P0）新增验收场景

**现状**：25、35 节共 8 个验收场景（A-H），均无合规与客户召回场景。

**修改建议**：新增两个场景：

**场景 I：合规闭环**

1. 医生（已完成执业备案）开具处方，含麻醉药品，系统强制单独开具且不超一日量。
2. 处方次日未发药，系统标记超期（租户配置当日有效时），药房无法发药。
3. 门诊完成后 24 小时归档检查生效，逾期未归档进入工作台待办。
4. 打印处方笺为三联格式，含前记、正文、后记。
5. 未备案的医生账号无法开方（按钮不可用且 API 拒绝）。
6. 病历满 3 年后的销毁流程需要机构负责人批准并产生审计记录。

**场景 J：流失召回闭环**

1. 客户 180 天未到店被标记为沉默并进入流失预警。
2. 门店按分群发放定向优惠券（营销授权为已授权的客户才接收）。
3. 前台创建回访任务，登记回访结果。
4. 客户通过微信小程序查看疫苗记录并在线预约复诊。
5. 到店消费核销优惠券，报表统计召回成功。
6. 营销授权已关闭的客户全程未收到营销消息，但仍收到医疗提醒。

## 4. 不建议采纳的方向（避免范围蔓延）

以下市场热点经评估不建议纳入当前版本 PRD，仅记录理由：

1. **自建在线问诊平台**：与互联网医院正面竞争，投入大、资质复杂，目标客群不需要（见 M-09 预留方案）。
2. **自建 B2B 供应链商城**：平台型业务，与 SaaS 工具定位冲突（见 M-11）。
3. **医学设备直连与 DICOM PACS**：PRD 已正确排除，调研未发现改变该决策的新依据。
4. **AI 自动诊断**：维持排除。市场主流做法也是"AI 辅助 + 医生确认"，见 M-08 的折中方案。
5. **宠物保险直连结算**：保险公司接口标准未统一，维持排除，先做理赔材料输出（M-06）。
